# Task 5: plain-prose generation coordinator and atomic bootstrap

Status: proposed bounded design for root review. This document implements no coordinator and enables no production dispatch. It composes the reviewed plain-input, profile, preparation and writer primitives. Code, rich documents, archives, repository history, provider synchronization, bulk dispatch and managed source deletion remain separate integration work.

## 1. Outcome and scope

An explicitly invoked coordinator accepts a complete local plain-prose inventory, captures immutable bytes and configuration, prepares all evidence and vectors, and publishes one complete verified generation. Refresh keeps G1 active while G2 is prepared and staged. First conversion keeps legacy evidence serving until one transaction installs and publishes the complete first generation. Failure before that commit preserves the original serving state.

Initially support local `text` and plain `file` sources using explicit `ByteInput`/`FileInput` inventories. Reject code, rich reader outputs, binary content and containers, rather than publishing a partial source. An excluded item is accepted only through an explicit configured exclusion. The operation never calls the legacy source-wide clear or directory-removal routines.

There is no new durable bootstrap reservation. Bootstrap workers may compute the same input concurrently; the final source lock and compare-and-swap admit one winner. This spends extra computation in the uncommon race but avoids both a new reservation protocol and premature managed classification. No generation lease exists during detached bootstrap preparation. Its heartbeat checks authorization, suppression and cancellation only. Refresh acquires a normal durable generation build lease before source-bearing inference.

## 3. Proposed APIs and file ownership

Create `src/hippo/ingest/prose_generation.py`, `src/hippo/knowledge/build_authority.py`, `tests/unit/test_prose_generation.py` and `tests/unit/test_build_authority.py`. Keep the coordinator orchestration separate from a small local authorization/lifetime helper. Add narrow controlled build-failure/publication checks in `store/generations.py` only where the current API cannot express them. Reuse the writer core; do not duplicate evidence or vector algorithms. No context, retrieval, pipeline entrypoint or schema changes are planned here.

Proposed public entry point:

```python
build_plain_source(
    ctx,
    *,
    source_id: str,
    actor: BuildActor,
    inputs: tuple[ByteInput | FileInput | ExcludedInput, ...],
    options: PlainBuildOptions,
    raw_store: RawArtifactStore,
    embedding_spec: EmbeddingSpec,
    operation_id: str,
    should_stop: Callable[[], bool],
    on_progress: Callable[[BuildProgress], None] | None = None,
) -> BuildReceipt
```

`BuildActor` is an explicit authenticated reader identity or explicit trusted-local maintenance actor; `None`, preview and synthetic reader identities are invalid. The actor carries no bearer token/password and confers no provider access. `PlainBuildOptions` is frozen: pipeline/parser/materializer versions, effective chunk size/overlap, synonym threshold, empty policy, capture limits, maximum decoded characters/chunks/prepared rows/prepared bytes, writer batch size, lease duration and renewal interval. Separate input-affecting configuration from operational scheduling limits; both must be validated before work. No whole `Config`, endpoint credentials or raw filesystem path enters the accepted manifest.

`BuildReceipt` contains source ID, generation ID, publication event ID, exact accepted-input hash and outcome (`published`, `already_current`, `already_published`). It contains no original text, paths, manifest JSON, policy inventory or exception body. A receipt identifies that operation's committed generation; it does not promise the generation remains the current head after return.

Use injected clock, controlled hooks and MockTransport clients in tests. Test-only fault hooks must not become arbitrary callbacks inside a transaction in production.

## 4. Source authority and lifetime

At entry, capture authorization and suppression epochs **before** resolving the live actor/source/workspace. Capture the source's control descriptor: ID, workspace, kind, owner, access role/rank, managed classification, active generation, and canonical source input configuration. Exclude counts, progress and `updated_at`; they change during routine work. Re-read this descriptor at mutation admission and publication, not only the epoch counters: `update_source(meta_json=...)` is not an authorization mutation.

For a reader, load its live enabled user and role, clamp rank to the supplied actor scope, require `Principal.may_manage_source` and an enabled workspace membership from reviewed mapping authorities. Preserve the owner exception but never use ownership to invent a workspace identity. Recheck live capabilities; a stale admin object is not an authorization grant. Bootstrap of local legacy sources requires the same explicit mapped reader prerequisites so conversion does not silently make the invoking owner unable to read managed evidence. Open/preview callers remain on the legacy route; this primitive rejects them. An explicit trusted-local maintenance actor is an internal capability for this local operation, never an HTTP/stdio fallback or provider credential substitute.

For new local artifacts use `AccessPolicy(origin='local_curated', scope_key='source:<source-id>:plain-prose-v1', mode='workspace', workspace_id=...)`, with no connector/provider identity. This expresses the local source's curation authority; current source ownership/rank and workspace membership still intersect it in `EvidenceAccess`. Do not derive allow-users from a one-time role expansion. Do not adopt `legacy_unknown` policies. Existing explicit local artifact policies and mutable presentation fields must be reused exactly rather than overwritten to the broad default. Refuse tombstoned/suppressed artifacts or incompatible/provider policies. New spans use their original artifact policy. An existing policy may be reused without refreshing its verification timestamp; expiry is not extended by indexing. New local policy creation is an authorized, auditable coordinator mutation.

A build guard captures immutable actor/control inputs and expected epochs, has a sticky failure/cancellation latch, and validates before/after raw reads, model metadata, every source-bearing HTTP attempt, each detached preparation checkpoint, each refresh batch and final response construction. Authorizing an original input must precede sending any of its text to the model. For refresh, check policy expiry/suppression on all accepted original inputs even if later chunks skip them. The accepted manifest is internal bookkeeping, never model input or a reader-facing inventory.

Use `LeaseHeartbeat` for the owned worker, with a coordinator-specific error wrapper/message. During bootstrap its callback performs authority/cancellation checks only. During refresh it additionally renews the exact claimed job with owner/fence, checking expected authority/suppression inside the renewal transaction. A failed renewal is sticky even if the store later recovers. Stop and join workers outside database transactions; partial thread start and close/error paths require tests. One preparation owns its runtimes and guard; do not reuse a failed adapter for a retry.

## 5. Deterministic input assembly

1. Resolve `ResolvedEmbeddingProfile` and `ResolvedOpenIEProfile` with live guards outside any transaction. Construct the strict `ProfiledEmbeddings` and `GuardedOpenIE` runtimes. Use their safe descriptors only; do not serialize clients/endpoints. Resolution/bracketing proves observable model identity on the trusted server, not request-level digest attestation.
2. Build configuration from `prose_configuration(...)` plus explicit versioned reader/chunker/materializer and input-selection settings. Record **effective** chunk size and overlap after the chunker's clamp, decoder behavior, all captured source input/title settings and explicit exclusion/empty policy. Changing a source title affects generation identity only if that title is used in rendered chunks; prefer deterministic logical-path titles in this primitive. Capture limits remain in the canonical AcceptedInputs manifest. Operational worker count, progress and observation timestamps do not enter representation identity.
3. Sort descriptors by normalized logical path before capture. Pass the complete inventory to `capture_raw_inputs`, with cancellation and size bounds. It writes immutable raw objects and canonical manifest bytes. An accepted partial subset is never substituted after failure. Mutable files are copied once; all subsequent reading uses captured raw objects, not live source files. Provider revision is caller-supplied immutable identity or None, never mtime/inode.
4. Construct original Artifact identity from workspace/source/kind `file`/logical path and no provider. New revisions use accepted hash, provider revision, raw URI, lifecycle active and fixed observation time. If the ID exists, reuse the **entire immutable existing revision** (including observation timestamp/metadata) after validating captured fields; do not recreate it with a new observed-at value. Likewise preserve existing Artifact URI/policy/deleted state during preparation and compare it at install. A concurrent mutation aborts; it is not silently overwritten.
5. Construct one `kind='manifest'`, external ID `accepted-inputs-v1` Artifact, and its immutable revision from `accepted.manifest.sha256`, `.uri`, and metadata exactly `{'accepted_manifest_v1': json.loads(accepted.manifest_bytes)}`. Reuse an existing equal revision. The manifest does not list itself as a raw input, and contains no generation/output IDs. A file literally named `accepted-inputs-v1` cannot collide because the artifact kind differs.
6. Build `generation_for_inputs` over every original pair plus the manifest pair, captured config and expected parent. A configuration-only rebuild reuses original revisions and creates a distinct manifest revision/generation. Reusing a staging generation requires its original creation timestamp; do not compare a freshly timestamped duplicate as if it were immutable-identical.
7. Read every raw object using `RawArtifactStore.read_bytes` and `read_plain_provenance` with one shared decoded-text budget. Refuse binary/code/rich outcomes. Prepare mapped chunks, materialize evidence with the accepted bindings, and append exact manifest membership. Construct `PlainProseInputs`, then `prepare_plain_prose` with guarded runtimes. All computation/model calls occur outside write transactions.

Empty is opt-in and explicit: distinguish empty inventory, all-excluded inventory, and accepted zero-byte/whitespace-only originals. Reject all-excluded inventory in this first coordinator even if `allow_empty=True`, to avoid mistaking configuration loss for an authoritative source deletion. Allow truly empty inventory or successfully read empty originals only when the captured empty policy permits them. Reader errors, budget truncation, cancellation, binary classification and dropped unsupported files never count as authoritative emptiness. Empty publication installs a complete empty generation; it does not physically delete retained evidence.

## 6. Refresh protocol

Perform authority/profile/capture/raw-read/chunk preparation first. Detached capture has no generation lease; it is bounded and guarded. Before inference, enter a short transaction, acquire authorization then source lock, compare entry epochs/control descriptor/expected G1 pointer, and validate the accepted local policies and record reuse. Persist new policy if required, staging Generation, claim its build, write exact Artifact/Revision/member inventory under `generation_write`, and bind the manifest through `bind_generation_embedding_profile`. Commit together. Inserting a staging Generation before acquiring that source lock is not allowed.

Any intentional policy mutation changes authorization epoch. Under the same lock, compare the original epoch before that mutation and capture a new expected epoch **after only the known coordinator-owned mutation**. Revalidate live actor/source/policy authority locally before accepting that new baseline. Use it for subsequent guards/writer calls; never reset the baseline after releasing the lock. The controlled profile marker changes content epoch only. Replacing global settings or modifying existing policies is not a coordinator-owned mutation.

Start the job renewal worker outside the transaction, run guarded source-bearing inference, then call `write_staged_prose` with exact job/owner/fence and post-admission authorization/suppression epochs. G1 remains selected through all batches and seal. Before publication, run final remote/model guards outside the transaction; stop/join the renewal worker outside the transaction and check its sticky state. In the final transaction, lock and recheck live actor, original control descriptor, expected epochs, all relevant policies/deadlines, exact seal/binding and the still-live job. Publish by `publish_staged_generation(expected_parent_id=G1, expected_suppression_epoch=...)`. Do not call the legacy `publish_generation` compatibility method.

The existing strict publish method checks suppression/fence/seal/parent but not the caller's captured authorization epoch. Therefore the coordinator's encompassing publication transaction must perform that explicit check before and after publication, with no external callbacks. This is not satisfied by a check just before entering the transaction.

No source-bearing calls occur after the final remote guard. Lease expiry inside the bounded publish transaction still causes rollback through `_check_build`; stopping renewal is not permission to extend a lease without checks. Build completion and source presentation updates occur in that same commit. Final receipt validation outside the transaction may deny release after a later permission change, but must not mislabel the already committed generation as failed or roll it back.

## 7. Atomic legacy bootstrap protocol

Until detached output is complete, persist **no Artifact, Generation, managed flag, policy or staging evidence**. Legacy source rows/graph remain serving. Keep heartbeat status in memory only; do not overwrite a ready legacy Source with partial build state. Source-local in-process Jobs may reduce duplicate compute later; they are not the safety mechanism.

After preparing and validating all output/bounds, run final remote checks; stop/join the authority worker; check the sticky state outside the transaction. Then:

1. Enter one outer transaction and acquire authorization/source lock. Recheck initial epochs, actor/policies/control config, true legacy classification (including absence of Artifact/Generation rows), no active generation and no conflicting live build. Reject a racing conversion before any write. If it already committed exactly these accepted inputs, the separate authorized receipt path may return `already_current` after proving equality.
2. Install the local policy, Generation and managed flag, then claim the generation job within this transaction using a fresh owner/fence and lease deadline from the store clock. Under that fence install the exact accepted original/manifest records and revision members. Revalidate live actor/source/policy authority and capture the post-own-mutation authorization baseline under this lock, after all authorized setup mutations that can change it.
3. Under `generation_write`, validate the installed original/manifest pairs and exact members, then bind the verified profile. Invoke callback-free `_write_batches`, `_write_batch`, `_seal` using the post-own-mutation epoch baseline. No `on_progress`, cancellation callback, model/profile validation, filesystem operation or worker start/join is permitted here.
4. Run local bound profile, seal, source/actor/policy/epoch/fence validation; publish with expected parent None; write final source presentation, and commit. Verify the lease is still live at publication. Rollback of any step removes every new marker, policy, member, native row, event and pointer update from that transaction, leaving legacy rows and their old graph serving.
5. Return a guarded receipt. Retain old legacy rows as unselected data after successful conversion; their removal is later generation-aware migration/collection work.

Cancellation is cooperative: the last external `should_stop` checkpoint is before transaction admission. Once the bounded no-callback commit transaction starts, a concurrent cancellation request cannot undo a successful commit; report its committed receipt if still authorized. Source permission/suppression changes serialize through the same authorization lock and can deny final release. If mid-transaction cancellation is required later, introduce an explicit in-memory cancellation token checked locally at writer boundaries; do not call an arbitrary application callback under the lock.

A source control comparison may need two explicit forms: the captured pre-conversion form and the permitted post-own-managed-flag form. Never compare the latter to the initial descriptor as an unexplained mismatch, and never accept unrelated field changes under that exception. Authorization changes caused by creating the policy/managed flag are expected only within this locked transaction. There is no need for a worker to renew the bootstrap job during the no-I/O transaction; the lease must outlast the bounded operation or the operation rolls back.

Set explicit bootstrap limits before opening the transaction: at most 1,000 chunks, 50,000 prepared persistence records/dependency edges, and 64 MiB of canonical prepared row payload including vector bytes, in addition to the existing raw/decoded limits. These are proposed conservative testable ceilings, not measured performance promises. Count deduplicated emitted writer records plus accepted records, memberships/manifests and fixed lifecycle writes; count oversized individual rows. Reject over-limit builds without installing any managed state; do not split bootstrap across commits. Store elapsed-time/lease checks remain the authoritative timeout safeguard. Larger sources require a separately designed shadow-bootstrap state or reviewed bounds, not silent truncation.

## 8. Idempotence, failure and recovery

The explicit coordinator API resolves an operation receipt under the captured source/authorization lock by source, rebuild kind and `operation_id`. Multiple matches or a different accepted manifest/configuration reject. An exact completed operation returns its original event after validating its job/owner/fence payload, generation parent, verified profile and seal, including when that generation has retired. Current accepted-input authority still applies. This lookup makes no new lease claim and never changes the current head. A different operation with the same active inputs returns `already_current`.

- **Already current:** after guarded profile/capture and local active-seal validation, compare accepted input manifest/config/profile to the active generation's `manifest_hash` contract. Do this before generating a new child merely because parent participates in identity. If equal, return its committed event as `already_current` without inference or writes. Do not compare only chunk count or tag. This path still validates authority, raw manifest and current seal; it never rebrands tag-only generations as verified.
- **Live duplicate:** an equal existing job may be reused only by its exact owner/job key/fence. A different owner gets Busy; it cannot adopt a live job. `operation_id` is stable for retries, not content identity. Publication receipt retries use the original credentials and generation/parent, not a newly claimed token.
- **Staging retry:** identical prepared output may replay writer batches idempotently. Persisted conflicting generated output is not overwritten. Since OpenIE is not guaranteed deterministic, re-running inference after process loss must use controlled failed-generation cleanup/reclaim, then regenerate; it cannot append a second interpretation to the existing partial attempt.
- **Ready retry:** with a live matching lease, validate exact bound seal then publish without rerunning inference. Once expired, existing recovery marks ready/staging failed; reclaim only through the existing controlled failed-generation retry path. No implicit lease revival.
- **Failure/cancellation:** stop/join heartbeat first, outside any transaction. If still the holder, use a narrowly controlled `fail_generation_build` transition to mark the unpublished job/generation failed or cancelled and clear its active-build pointer under source lock/fence; never touch G1. If the lease/fence is lost, do not mutate the winner's state. Current `discard_generation` also collects rows; avoid invoking it automatically when a simple failure marker is sufficient. Expired-state recovery remains responsible when no valid holder can write. Add the small failure transition only if needed; do not use generic MaintenanceJob/Generation writes to bypass their guards.
- **Crash:** before bootstrap commit only conservative raw blobs may remain. During bootstrap transaction database rollback preserves legacy. Refresh crash leaves invisible staging/ready data and G1 active; restart recovery invalidates expired holder, then exact retry can proceed. Crash after publication but before response is resolved by the immutable publication receipt. Source deleted/suppressed during work prevents subsequent calls/writes/publication and never causes source recreation.
- **Source status:** serving state and build attempt state differ. Preserve G1/legacy ready status during attempts; report refresh progress in owned job/in-memory progress. On success update source counts from the newly sealed generation through generation-aware counts, not raw global counts. Only a source with no last-good serving generation may have failed ingest status. Persist bounded error codes, never raw model errors that can quote private text. A post-commit release failure is not a failed build.

## 9. Raw storage, cleanup and privacy

Raw content-addressed storage is outside database atomicity. Keep a dedicated configured raw root separate from source directories and caches. Use the existing trusted-local-root contract, hash-verifying reads and atomic no-overwrite publication. A successful raw write may precede a failed capture or transaction and remain orphaned; that is allowed.

This coordinator performs **no raw deletion**, including objects it just wrote: another concurrent build may share them, and a bootstrap worker's uncommitted references are not visible to the database. Until a separate raw-GC protocol accounts for in-flight captures (pins or an explicit coordinated exclusion), disable automatic raw GC for this store. Later collection must trace active/retained generation and snapshot references, manifest originals, live builds, saved results and active captures. Generation collection alone does not prove a raw object unreachable. Clean only task-owned temporary files through the raw primitive's ownership rules.

Internal accepted manifests and progress may contain hidden inventory. Return only the safe receipt and use existing audience-scoped source DTOs on reader surfaces. Never put manifest bytes, whole config, raw path, private exception text or inferred triples into generic status/log messages.

## 11. First increment: prospective build authority

Implement only `knowledge/build_authority.py`, its focused tests and gate ledger before coordinator orchestration. Frozen `BuildActor` represents a real reader (user ID and maximum rank) or an explicit trusted-local internal operation. `SourceControl` captures source/workspace/kind/owner/access role/rank, managed classification, active generation and canonical input metadata (all keys except the explicit output-only `chunks`, `documents`, `counts`, `code`, `progress` fields). Presentation/progress/count fields do not participate. Real reader identity/capabilities are reloaded; open/preview/synthetic identities are rejected.

`AcceptedBuildInputs` holds an immutable tuple of exact Artifact/Revision pairs, optional exact EvidenceSpans and explicit planned missing AccessPolicies. Empty accepted input is supported for pre-capture source authorization. An authoritative empty generation later supplies its actual accepted-manifest revision. New policies must be the exact source-scoped local-curated workspace policy described above; they cannot replace existing policies or alter an existing Artifact's policy. Existing records must match the accepted snapshots. Policies, groups, memberships, suppression and source controls remain live reads.

`capture_build_authority(store, source_id=..., actor=..., accepted=..., clock=...)` captures epochs before live checks and returns `BuildAuthority`. Its private read-only overlay supplies just the accepted artifacts/revisions/spans and planned absent policies alongside live authorization rows to existing `EvidenceAccess`. Use exact accepted revision selection and require every accepted revision/requested span to survive core authorization. A narrow shared `EvidenceAccess.require_source(source_id, query_mode="current")` factors the existing workspace/identity/source/suppression boundary; the empty guard uses it without synthetic evidence. Existing build() uses the same factored source and suppression helpers. No prospective proof is returned to retrieval, no generation selection is fabricated, and no staging records are written. The helper is a build permission check, not evidence publication or raw-byte attestation.

`check_local()` uses only store reads and the local clock and may run inside a caller-owned transaction. It validates both epochs, source controls, live actor/source-management authority, accepted record identity and core evidence policy results. `check(checkpoint=None)` refuses ambient transactions, runs the local check, optionally invokes the external checkpoint, and repeats local/latch validation even on callback errors. Failure is sticky; `close()` prevents future use. The coordinator owns any heartbeat/thread and uses `check_local` under its short local transaction while renewal is active; this primitive starts none. `bind_inputs(accepted)` owns one source/authorization transaction lock and derives a guard using identical captured controls/epochs while validating its parent before and after; it cannot reset authority after revocation. It has no generic epoch reset/rebase method: subsequent coordinator setup must first validate under its lock, perform specifically authorized setup writes, then construct the next guard under that same lock and validated authority.

## Coordinator implementation notes

The implemented `_Run` owns a thread-safe sticky failure latch. Every local authority/lease check runs in a short store transaction; arbitrary progress and cancellation callbacks run outside that transaction and are bracketed by local checks. The heartbeat may legitimately own another thread's transaction while HTTP is in flight. Tests therefore instrument transaction ownership per thread; a store's shared depth counter cannot distinguish that case from an ambient caller transaction. `BuildAuthority.check` and the public staged-writer wrapper retain their original ambient-transaction contract. The coordinator uses `check_local` and the callback-free writer cores, stopping and joining its worker before bootstrap admission, publication and final cleanup.

`plain-bootstrap-budget-v1` reserves 12 logical lifecycle records and 16 KiB of canonical framing/seal/job/event/epoch overhead, plus the actual source/workspace/operation identity strings multiplied by that record count. It adds the canonical final source metadata envelope (using configured upper bounds for counts), Generation and planned-policy payloads, every accepted Artifact/Revision/member and every emitted writer record. These are conservative logical-record and canonical-payload bounds; they do not estimate engine indexes, database pages, lock-counter writes or WAL bytes. Exact-at and one-unit-over tests define admission. Large source metadata rejects before any model request. Bootstrap row/byte ceilings and scheduling options remain operational settings, outside representation identity; raw capture limits retain their existing accepted-manifest treatment.

The coordinator is an explicit library API. It does not activate production ingest routes, install models, mutate model configuration, remove source-wide data or collect raw objects. Automatic raw collection remains unsupported while detached captures have no durable pins.

**Known limitation (deferred 2026-09-11).** The coordinator's entry probe and `BuildAuthority.check` read the store's process-global transaction depth, so concurrent `build_plain_source` calls in one process can be spuriously rejected with an ambient-transaction error that the caller did not cause; the same probe can withhold a `BuildReceipt` from a build that already committed correctly. Fixing it needs the store to expose per-thread transaction ownership, which is a store-layer change outside this slice.
