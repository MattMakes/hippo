## API and ownership

- `Context.graph_for(access, *, settings=None, structural=False)` propagates the explicit flag through its private builders. `query_access` and `query_session` accept the same keyword; omitted/false calls preserve existing mock and production call signatures.
- `acquire_query_snapshots(..., profile_fingerprint=None, source_profiles=None)` requires exactly one profile selector. `source_profiles` is copied and validated before use, has exactly the requested source keys and nonempty string values, and produces groups by `(workspace_id, declared_profile)` inside one transaction. Existing scalar calls preserve their behavior.
- `project_managed_graph(full, store, authorized, *, embedding_profile=None, source_profiles=None, structural=False, ...)` accepts `full=None` only for structural calls. Structural calls require an exact copied source/profile mapping and one exact workspace proof. Raw native rows validate against their own generation/profile, original/view text and complete provenance, without any cached majority-filtered matrix. Dimensions validate per generation; prose similarity stays within each source/profile. Workspace assembly preserves canonical objects shared by multiple source observations.
- `LegacyDenseVector(lane, projected_id, dimension, values, support_passage_ids=())` is a frozen structural-only record. It has no generation or profile fields. `GraphIndex.legacy_dense_vectors` contains only retained untagged passage/native-Fact rows from an already source-authorized legacy graph. `structural_legacy_graph(graph)` copies those rows into immutable values and replaces dense matrices with `(N, 0)` arrays. Managed bindings remain distinct.
- Scoping, composition and fingerprinting preserve the union of these explicitly distinct rows in existing passage/Fact order. Legacy Fact support is restricted to the retained visible legacy passages; managed Fact closure cannot become partial. Legacy-only default graphs and fingerprints remain unchanged.
- Root-approved topology refinement: frozen `StructuralCodeEvidence(node_id, generation_id, source_id, original_span_ids)` retains selected code observations that have no own retrieval Passage. Validate projected node/source, selected generation consistency and complete original dependencies. Scope code by this explicit binding and keep its original citations; never fabricate a Passage or vector. An additive fingerprint payload includes these bindings and their original citation contents only when such code evidence exists. Structural hashes can therefore differ from the old default projection where that projection omitted this authorized topology.
- Shared code contributions are unique by `(node_id, generation_id, source_id)`. Build display attributes independently from each source's authorized observations; all fields other than source labels and derived degree must match, otherwise raise `ProjectionError`. Equal observations merge one canonical node, with deterministic minimum contributing source ID. Source scoping filters contributions and resets that source ID. Shared typed entity observations likewise cannot silently select one source's conflicting attributes.
- Frozen `StructuralObjectEvidence(node_id, generation_id, source_id, observation_ids, original_span_ids)` records each source's selected authorized noncode typed observations, including standalone observations with no Passage or assertion. Immutable sorted observation IDs and original IDs bind the actual selected rows; original citations and generation/source correspondence remain validated. `GraphIndex.structural_object_evidence` survives assembly and composition, contributes an additive fingerprint only when nonempty, and scopes by source. Visible observation contributions retain typed entities independently of passage mentions; assertion support alone never invents an observed endpoint. Shared equal attributes may merge while scope filters contributions and complete relationship supports independently. Suppression removes the corresponding observations and dependent topology. Retrieval dispatch must classify these generation contributors even without any dense/code/relation row.
- Frozen `StructuralRelationEvidence(subject_id, object_id, predicate, weight, assertion_version_id, derivation_group, original_span_ids, source_generations)` retains complete typed assertion support groups, including originals with no Passage. `source_generations` is a canonical immutable tuple of `(source_id, generation_id)` pairs, exactly covering support-original sources from the selected generation map; it agrees with dense/code generation provenance. This retains relation-only contributors without consulting mutable current pointers. Source scoping retains a relation only when all its original support remains and both endpoints survive. Rebuild its arrows and aggregated `Edge.omega`/`code_kinds`/igraph weights from retained groups. Endpoint survival alone does not retain a relationship. The additive provenance fingerprint commits relation contributions, their source/generation mapping and original citation contents.

## Selection and lifetime

Structural context obtains visible sources and exact per-source proofs under the existing transaction/authorization epoch. Declared generation profiles are read locally; no Ollama attribute or HTTP call is permitted during graph selection or validation. Strict sources acquire all references atomically through the profile mapping. Non-strict historical managed fixtures retain their existing explicit compatibility interpretation.

The legacy branch calls `load_generation_graph(generations={}, legacy_source_ids=visible_legacy_ids, ...)` separately before its existing eligibility rules. Thus hidden, managed and staging rows never choose a legacy majority dimension. This preserves rows retained by the existing visible legacy eligibility algorithm; it does not recover legacy rows already discarded by that algorithm. Recovering those rows requires a separate follow-up contract.

Construct managed components from one exact workspace proof each and each selected generation's own profile/raw rows, then compose disjoint workspaces with the explicitly adapted legacy component. Recheck that acquired snapshot generation IDs exactly match the initial selection before projection; a read-committed G1/G2 race fails and closes all references. Apply the existing legacy passage-support scoping rule before adaptation for reader and managed-composition paths so orphan legacy code does not gain visibility. Attach only local authorization, proof and snapshot checks. Any build error after reference acquisition closes the bundle; pinned generations remain valid across pure publication, and revocation/expiration denies use. Default production paths remain unchanged.

## Acceptance fixtures

1. Different managed dimensions/profiles in one workspace retain originals, rendered views, prose Facts, code and citations with an Ollama property trap; dense retrieval remains unavailable.
2. Hidden/staged incompatible rows cannot change visible topology, counts or fingerprints; managed rows cannot affect a visible legacy majority.
3. Mixed managed/legacy composition preserves retained native legacy Facts with explicit support and canonical values, without invented generation/profile. Source/empty scopes remain valid.
4. Snapshot mappings require exact immutable keys/values, group by workspace/profile, and injected failure on a later group leaves no acquired references.
5. Pinned old generation survives publication; suppression/revocation/expiry denies current use; session success and failure close all references without accessing model properties.
6. Existing default dense, projection, context, snapshot and query-session regressions remain green. Fake and Ladybug precede any explicitly root-reserved Neo4j run.
