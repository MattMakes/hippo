# Task 5 accepted input and original evidence contract

Status: root-approved implementation contract. The separately reviewed raw artifact primitive is implemented; reader/chunker/preparation integration remains in progress. This specifies the input/provenance portion of `rag-it-all-task-5-pipeline.md` and consumes the implemented schema5 contracts in `rag-it-all-task-5-derived-evidence.md`. It does not authorize production dispatch changes or replace the reader/projection gates.

## Decision

Capture immutable raw inputs first, retain a mapping from analysis text to original units, and carry that mapping through shared chunk preparation. Preserve existing public `Document`, `Chunk`, `extract_code`, `read_history` and `index_source` behavior for legacy callers. Add provenance-bearing preparation results alongside them; do not recover origins by searching chunk text or parsing display titles after transformation.

An EvidenceSpan contains exactly the original unit or supported slice addressed by its locator. A chunk becomes an original dense passage only when its retrieval text exactly equals one such span. Every other case becomes a RetrievalView with all contributing original dependencies. This includes paragraph normalization and overlap, rich-format heading/table rendering, cleaned docstrings, code placeholders and commit touched-symbol lists. Generated retrieval text never becomes an EvidenceSpan merely because the old indexer called it passage text.

The source capture, text extraction, syntax preparation and model preparation stages remain separate. Generation identity is constructed after the complete raw inventory and configuration are accepted, before generation-scoped code IDs, views, vectors or inferred extraction outputs exist.

## Minimal DTO and service surface

Use a focused `ingest/provenance.py` for immutable input and chunk mapping types. These are preparation values, not new knowledge tables. Represent collections as tuples, avoid live store handles, and make mutable legacy Chunk/CodeGraph values copies at the adapter boundary.

| Type / API | Required fields or signature |
| --- | --- |
| `RawInput` | `input_key`, `logical_path`, `media_type`, `raw_uri`, `raw_hash`, `byte_length`, `provider_revision`, `container_chain`; source/workspace/policy supplied by accepted build scope. No absolute checkout path in identity. |
| `InputDisposition` | `input_key`, `outcome` (`accepted`, `excluded`, `failed`), closed `reason`, optional byte count/hash where obtained. Cancellation is a build outcome, never an exclusion. |
| `AcceptedInputs` | Source/workspace, ordered RawInputs, dispositions, accepted manifest bytes/hash/URI, captured reader/parser/chunker/history configuration, optional repo HEAD and first-parent commit inventory. No generated vectors or extraction output. |
| `OriginalUnit` | `unit_key`, raw input key, typed SourceLocator, original text, reader profile, and original character range where that locator supports a range. Its locator precision is explicit. |
| `OriginalSegment` | Reference to OriginalUnit plus a half-open character range within its text. Repeated overlap references are retained in rendering order. |
| `GeneratedSegment` | Literal text, renderer rule identifier, and explicit original-unit dependencies; no fake source offset. |
| `ProvenanceDocument` | Immutable copy of legacy Document fields, original units, and ordered segments that reconstruct `analysis_text` exactly. A parser input byte-offset map covers UTF-8 encoding of analysis_text. |
| `PreparedChunk` | Legacy ordinal/title/text/defines/extract_text values, stable chunk key, ordered retrieval segments, ordered extraction-input segments or explicit skip, original unit dependencies, and declared support chunk keys. |
| `CapturedHistory` | Ordered commit records, immutable raw commit/diff/blob inputs, first-parent and shallow-boundary inventory, raw historical paths, rename mapping inputs, full hunk records, and explicit coverage outcome. No generation-scoped native IDs yet. |
| `capture_source_inputs(source, settings, limits, *, staging_root, raw_sink, should_stop) -> AcceptedInputs` | Bounded source I/O; freeze input inventory before interpretation/model work. |
| `read_provenance(inputs, *, raw_reader, reader_profile, budget) -> tuple[ProvenanceDocument, ...]` | Read accepted immutable bytes and return legacy-equivalent analysis text plus original mapping. No store/model calls. |
| `prepare_chunks(documents, code, history, *, size_chars, overlap_chars) -> tuple[PreparedChunk, ...]` | Shared chunking decisions with provenance retained; no persistence. |
| `materialize_chunk_evidence(prepared, generation, artifacts_and_revisions) -> PreparedEvidence` | Resolve original units to spans, build schema5 views/derivations and view-aware passage IDs, and produce explicit extraction input/support bindings. No embeddings, model calls or writes. |

The repository currently has no dedicated immutable raw blob service. Implement a small separately tested `RawArtifactSink`/reader seam before a coordinator uses these APIs: bounded atomic content-addressed writes in a task-owned raw area, hash verification on read, and returned immutable references. Cache directories and mutable `source_dir` files are not this service. Failed preparation may discard only its own temporary directory; retained raw objects follow generation/snapshot reachability, not that temporary directory's lifetime. The proposal does not imply that raw storage already exists.

## Capture and accepted identity

For pasted text, capture the saved source bytes before `.strip()`. For uploads, retain the exact uploaded bytes. For archives, retain the container plus exact accepted member bytes or an immutable verified container/member read reference. Member identities use normalized, source-relative paths and an explicit container chain; reject ambiguous duplicate normalized paths, absolute paths and parent traversal in managed capture. Classify archive symlink entries explicitly rather than interpreting their target text as a normal file. Do not create filesystem paths by parsing `archive.zip:member` titles. Keep the existing legacy zip path untouched.

For repositories, clone/fetch into a fresh build-owned checkout, resolve one exact HEAD and enumerate the accepted tree at that revision. Prefer reading accepted blobs by the pinned Git object identity; a mutable working tree is not the authority. Record configured depth, first-parent selection, exclusions and shallow boundaries. Supply the captured settings to both clone-depth and history code, replacing the managed path's present repeated live settings reads. A changed remote during model preparation does not mutate this build's accepted inventory.

An input key is structural: source-scoped relative file/member identity, or explicit history event/blob identity. The accepted list is stable and retains the current reader order as an explicit order key. Files omitted by configured format/junk/size rules appear as exclusions; a failed read/decode/parse of a required accepted input fails the build. Total text/archive/chunk/code/history caps remain enforced. A timeout or cancellation cannot silently shrink the inventory and become a different successful generation.

Persist a canonical accepted-input manifest as an ordinary `Artifact(kind='manifest')` with immutable raw bytes and a revision. It includes raw input identities/hashes/provider revisions, ordered inventory, exclusion policy/results and captured configuration. It contains no prepared chunk text, parser output, extraction result, generated IDs, vectors, build timestamps, absolute staging paths or machine-specific raw URI locations. Raw storage references live outside the canonical identity payload; hashes and logical identities establish equality. GenerationMember includes the manifest revision plus accepted original revisions, and `generation_for_inputs` receives that same inventory/configuration. The manifest is an audit/reproduction input, not an evidence grant inferred from JSON references.

Do not place changing reader-profile metadata into an existing original ArtifactRevision: revision identity uses artifact/provider revision/content hash, while metadata is immutable under that identity. Reader/configuration profiles belong in the accepted manifest and generation configuration; generated views carry their derivation profile. Raw artifacts/revisions can then be reused unchanged when only a reader or model profile changes.

One generation currently accepts one revision per Artifact. Therefore historical file blobs cannot share the current-file Artifact while selecting several commits. Use separate source-scoped history-event artifacts keyed by `(commit SHA, historical path, side/blob identity)` with their exact bytes. Keep the historical path in original locators and the HEAD path only in logical symbol correspondence. This avoids weakening the current one-revision-per-artifact invariant.

## Original slices and format precision

For plain UTF-8 text/code, OriginalUnit uses the exact decoded untrimmed source text under a declared BOM/error policy. Track original line starts, newline sequences and byte-to-character boundaries. `file_lines` uses one-based inclusive source lines. Slice complete original lines, preserving their actual content/newline policy; no substring search, regex title parsing or blanket arithmetic over Unicode bytes. The declared decoder profile records replacement decoding when used; replacement characters are not claims about recovered original bytes. UTF-8 byte hashes continue to address the retained raw input.

The existing file locator has no character offsets. A chunk cut inside a long line therefore cannot claim that its shortened text is the whole `file_lines` span. Use the complete original line(s) as EvidenceSpan and a RetrievalView for the shorter normalized chunk. This requires no invented character-offset locator or schema change. The internal segment offsets still verify which characters were used.

| Format | Honest original locator/unit | Retrieval transformations |
| --- | --- | --- |
| Plain text, Markdown, code/config | `file_lines` over retained decoded source, including actual heading/comment lines | Trim, sentence packing, blank-line normalization, overlap, omitted headings, placeholders and cleaned documentation become views unless text remains an exact original span. |
| Pasted text | Stable source input artifact with `field` locator for the captured body, or declared file_lines over its retained text artifact | Whole-body original allowed; chunks inside the coarse field become views over it unless a real supported line locator is used. |
| PDF | `page` with original one-based page and half-open Unicode code-point offsets in that profile's extracted page text | Joins across pages and inserted separators are views. No physical line numbers, bounding boxes or OCR precision are claimed. Empty pages retain their numbering; image-only pages are explicit no-text outcomes. |
| DOCX paragraph | `section` block indices/heading path defined by a versioned XML/paragraph extraction profile; count original empty blocks in the locator namespace | Markdown `#` prefixes and whitespace cleanup are views; preserve legacy paragraph-then-table analysis order while recording real original block identity. Do not claim page numbers. |
| DOCX table | `table_cell` with zero-based table/row/column from the supported body table enumeration | ` | ` and interrow separators are generated. Merged-cell aliases must be resolved/deduplicated explicitly, not treated as independent source text. |
| HTML | `section` block indices and heading path over retained source under the versioned parser profile | Entity decoding exposes original text content; synthetic heading markers, block separators and whitespace tidying are views. No DOM selector or browser-rendered layout is claimed. Script/style/template suppression follows existing behavior. |
| EPUB | Member-specific artifact plus HTML section units; explicit spine position retained separately | Chapter concatenation is a view, not a new original file. Missing/malformed spine fallback is declared; chapter identity does not depend on its display title. |
| Git commit | `field` locator for raw commit message/author headers under an explicit commit-object parser | Message cleanup and touched-symbol summaries are views; message inference uses only its selected original or cleaned message view. |
| Git change | `diff_hunk` referencing accepted base/head revisions and the real historical path; selected side has actual lines | Hunk summaries, aggregated churn and symbol names are derived; do not fabricate lines for an empty side of an insertion/deletion. |

Rich-format EvidenceSpan text is original content extracted at the supported unit precision, traceable to retained original bytes and the recorded reader profile. It excludes formatting invented for retrieval. A page or block locator refers to that supported extractor's stable unit namespace, not a precision the parser never supplied.

## Shared prose/code chunk preparation

Refactor private chunking intermediates so the string algorithm operates on mapped units. Offset-aware `split_sections`, paragraph/sentence splitting, hard cuts and overlap retain exact origins while making the same boundary decisions. A generated separator is represented as generated, even when it happens to equal whitespace in the original. Do not recover a repeated paragraph's location using `str.find`; identical text can occur at several different original positions.

Keep the current document and chunk order, source-wide ordinals, maximum-size rules and title conventions. For code, preserve container traversal: module header, container header, members grouped by ownership, then oversized parts in existing statement/window order. Rust impl/Go receiver methods may be outside the type's physical range; their placeholders must depend on their real declaration spans rather than stretch the type's original span to cover intervening code. A row with several discontiguous original runs becomes a view with separate spans for those runs.

Replace private `Row = (line | None, text)` with a row carrying the original run or a generated placeholder plus the member declaration dependencies used to construct it. `_pieces_from_rows` must return that mapping rather than discard it at `_text_of`. SQL retains the existing windows and data-object definition associations, with `extract_text=''`. An unsupported or failed grammar keeps the existing legacy fallback; the managed capability records whether fallback is permitted or fails required parser coverage.

Parser ranges are relative to the exact UTF-8 analysis buffer. Readers currently strip leading/trailing whitespace before extraction, and documentation helpers further transform text: Python `_docstring` uses `inspect.cleandoc`, TypeScript `_doc_before` removes comment markers. Record original parser-node byte ranges before cleanup and translate them through ProvenanceDocument's map. A cleaned signature/docstring is a view over the original declaration/comment span, not a substring with guessed coordinates.

Keep original and analysis coordinates separate until chunking finishes. Do not mutate Symbol.line_start to raw coordinates while `_chunk_symbols` still indexes trimmed analysis lines. The managed native/observation writer receives translated original coordinates, and generated displayed line references use those original coordinates. Legacy text/titles/IDs remain unchanged. Managed fixtures with leading blank lines, BOM, CRLF or trimming can therefore have corrected displayed coordinates compared with legacy output: this is an explicit, narrow provenance correction, not a silent promise of byte-identical generated labels. Ordinary fixture boundaries, code ownership, doc input and retrieval semantics remain the baseline.

Add nonstored origin ranges to Symbol/FileFacts or an equivalent cacheable sidecar at the walker boundary. Include declaration, body and documentation ranges used by derived outputs. Preserve Symbol.row()'s legacy schema. Retain origin sites for resolved data-object mentions and relation-producing syntax as well: a DataObject's name or CodeEdge's provenance label cannot stand in for its actual source line/declaration. Existing `(path, line)` mention sites permit honest whole-line evidence when finer parser ranges are unavailable; they do not justify a fabricated byte range or a generated SQL declaration. Bump syntax cache schema/walker versions if the serialized origin payload changes; old entries become misses. Cache hits rematerialize provenance and generation IDs from accepted inputs, and whole-source name resolution still runs. A cache cannot supply a citation locator unsupported by the raw input map.

Preserve the exact three-valued OpenIE gate: `extract_text is None` uses chunk text even when short; `''` skips; an explicit string uses the current 80-character minimum. Parsed bodies/DDL stay out of OpenIE, and only the first part of a split symbol carries its documentation input. Code references continue to scan the human input chosen by `_scanned`/`_is_prose`; generated touched-symbol names cannot feed back into REFERS_TO.

## History capture before generation-scoped materialization

Separate `read_history` into a capture stage and a pure materialization stage while preserving its legacy wrapper. Capture the pinned first-parent inventory, raw commit object/message, bounded diff bytes, and each historical source blob required for hunk attribution. A structured commit-object parser should supply original field boundaries; do not attempt to reverse formatted `_log` output into raw original evidence after `.strip()`.

After generation identity exists, materialize the same commit IDs with `node_namespace=generation_namespace(gen)`, parse historical blobs at their actual commit coordinates, and map their logical symbols to HEAD using the existing rename chain and symbol_key behavior. Both tree-sitter passes use accepted bytes; `_symbols_at` must not reach back into an unfrozen checkout during this phase.

Keep root-vs-first-parent diff semantics, explicit diff options, shallow-boundary behavior, innermost-own-range attribution, newest-first commit ordering and PRECEDES direction. Preserve every contributing raw hunk even though the legacy MODIFIES row keeps only the first position and accumulated churn. A managed MODIFIES observation can have alternative hunk proof groups for relation existence; any derived aggregate churn/card depends on all inputs used to compute the aggregate.

For a pure deletion, cite actual base-side deleted lines; the existing new-side anchor used for symbol attribution is not the deleted text. For a pure insertion, cite head-side added lines. Never manufacture a positive start/end range for a zero-line side. Rename-only commits remain modifications-free under the existing extraction semantics; retained rename records explain path correspondence without inventing a changed body.

`_chunk_commits` preserves message input and its existing size/truncation policy. The rendered touched-name list depends on the original commit/diff evidence and original declarations/observations behind every displayed name. `_commit_text` truncation counts are derived too. A message-only chunk can use a cleaned message view if trimming changed it. Empty messages with touched names still have an original commit field anchor and complete diff/declaration dependencies; they do not acquire fabricated original prose.

Capture must distinguish configured history depth, known shallow boundary, deliberate exclusion, budget truncation, unreadable input and cancellation. The legacy wrapper retains existing warning/partial behavior. The initial managed parity capability fails requested mandatory history preparation on unexpected loss; any optional/degraded policy must be explicitly captured and reflected in coverage. A partial mutable History object cannot establish a complete accepted manifest.

## Shared index preparation and writer boundary

Extract the reusable computation from `index_source` without copying its full pipeline. Suggested focused helpers are `prepare_passage_vectors`, `prepare_code_rows`, `extract_chunk_prose`, `prepare_fact_payloads`, and pure synonym candidate search over an explicitly supplied compatible corpus. Keep `refers_to_rows`, module_communities, name normalization, fact_text and existing code embedding eligibility rules shared. Model calls occur outside managed write transactions.

The legacy adapter preserves passage_id, global existing-entity/fact checks, orphan-lock behavior, source write diagnostics, global embedding metadata and graph-version publication. Its `_add_vanished` compatibility path remains isolated; it currently may embed after taking GRAPH_WRITE_LOCK and cannot be reused as a managed transaction helper. The managed adapter prepares all required entity/fact vectors under the captured profile, using the explicit embedding cache rather than trusting global Fact/Entity presence.

Materialize originals/views before calling models so the exact retrieval and inference text hashes are fixed. For each successful inference, create one ProseExtraction per declared input/profile with explicit support_passage_ids resolved from PreparedChunk support keys. Its input can be a dedicated documentation/message/normalized prose view distinct from the dense retrieval view. Every support passage's original closure must cover the inference input's originals. Generated views may add original context dependencies; all such dependencies participate in access checks. Do not multiply support merely because several retrieval views share one logical chunk.

PreparedIndex contains vectors, typed extraction outputs, original spans, views, derivations/dependencies, observations, native bindings and complete declared coverage. Its declared dense inventory equals its persisted native passage inventory; its expected successful extraction input set equals selected ProseExtraction input/profile tuples, with explicit skip outcomes separate from failures. The nine index_source counts remain legacy write diagnostics and are not redefined as inventory or publication authority.

An authoritative empty accepted source is valid only through an explicit managed empty-source policy. It is distinct from zero chunks caused by failed reading, parser loss, cancellation or budget truncation. No empty result authorizes source-wide deletion. Rebuild, failure cleanup and immutable raw retention remain the coordinator's responsibility under the parent pipeline contract.
