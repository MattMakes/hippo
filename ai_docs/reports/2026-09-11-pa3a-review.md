## QUALITY

The brief's direct questions first, then the findings.

**Is `plan_dispatch` the single classification path?** Yes, for dispatch. All five entry points (`add_text`, `add_upload`, `start_indexing`, `run_indexing`, `reindex`) route through it, and `run_indexing` re-plans from a fresh `get_source` so a source converted, tombstoned or re-permissioned between dispatch and worker is reclassified. There is no second predicate in the ingest layer, and no reachable path from a managed source to the legacy branch: `plan_dispatch` raises `ManagedActorRequired` before it can return `"legacy"` for a managed source (`:148–149`), and `legacy_source_cleanup` is the backstop. One predicate *does* differ elsewhere in the tree — Finding 9.

**The double-fault fix in `98aac44` — what if recording the failure itself fails?** Correct and well-reasoned. `_run_managed_indexing` (`pipeline.py:301–331`) catches the inner failure and logs source ID and operation ID alone; re-raising would hand `Jobs.start`'s `log.exception` (`jobs.py:37`) a chained traceback holding the original exception text, which is exactly what the mapper exists to prevent. I confirmed empirically that a `log.exception` record's formatted output contains the poisoned exception text. Both `BuildCancelled` and `AuthorizationChanged` derive from `RuntimeError`, so `except Exception` catches every coordinator failure family.

**`_refuse_if_indexing` ordering relative to actor and tombstone checks.** Correct. In `reindex` (`pipeline.py:529–551`) the order is: own-job-running → source-exists → `plan_dispatch` (actor + tombstone) → `_refuse_if_indexing` → legacy prepare. A managed source with no actor raises `ManagedActorRequired` rather than `Busy` when another source is indexing; that is the right precedence (refuse before mutation) and it is what deviation 5 records.

**Does anything key on `updated_at`?** No. I traced every consumer. `view_fingerprint` (`knowledge/replay.py:20–40`) is built from graph content — node IDs, passages, code nodes, facts, vectors, edges — never the Source row. `SourceControl.input_config_json`, the field a build's own authority is bound to, is `canonical_json` of `meta` minus the presentation keys (`knowledge/build_authority.py:88–93`), so it excludes `updated_at`. `store/generations.py:615` explicitly drops `created_at`/`updated_at` from shared-node payloads. Nothing in `status.py`, `web/`, or the eval/replay paths reads it. **Deviation 6 is closed: an `already_current` refresh moving `updated_at` invalidates nothing.**

**Does the actor closure survive a process-level job retry?** The question is moot: `Jobs` has no retry (`jobs.py:27–47` — one thread, `log.exception` on crash, `finally` pops the key). A re-run requires a fresh `start_indexing` call, which re-derives the actor from the current caller. The coordinator's `MaintenanceJob` `attempt_count`/`retry_at` fields are not driven by `Jobs` in this slice. So no stale actor can be replayed.

**`source_dir` delegation and import cycles.** Clean. `pipeline.source_dir` → `managed_activation.source_directory` (`pipeline.py:578–580`); `managed_activation` does not import `pipeline`, so there is no cycle, and the value is unchanged. Deviation 4 is the right call — two definitions of the ingress path is exactly the drift this plan warns about.

**Does `managed_activation` import from `knowledge/dense_session.py`?** No. Its `knowledge` imports are `access`, `build_authority`, `embedding_cache`, `embedding_profile`, `raw_artifacts`, `source_lifecycle`. The layering rule (ingest may import knowledge, not the reverse) holds in both directions. Related: Finding 11.

### Findings

**1. [major — coverage] The `reindex` entry point is never exercised for an eligible legacy conversion.**
`tests/unit/test_managed_pipeline_activation.py:359` · `src/hippo/ingest/pipeline.py:549–550`
*Why:* the plan's dispatch table names this row by entry point ("Existing eligible legacy `text`/plain file reindex"), and PA5's CRITERIA says "managed refresh and eligible conversion never call legacy preparation". `_prepare_reindex` is reachable only from `reindex` and `reindex_all`, so `test_an_eligible_legacy_reindex_converts_atomically_and_serves_legacy_until_publish` — which calls `run_indexing` — cannot execute the `if plan.mode == "legacy"` skip that the criterion is about. No test in the slice calls `pipeline.reindex(ctx, id, build_actor=actor)` on a source that is eligible but not yet managed. The branch is correct by inspection; it is unguarded against regression.
*Fix:* change that test to drive `pipeline.reindex(w.ctx, source, build_actor=w.actor)` instead of `w.build(source)`. The `_clear_passages` monkeypatch already in the test then also covers `_prepare_reindex`, and the `/api/chat` hook assertions are unaffected. One-line change, no new fixture.

**2. [major — coverage] The redaction test cannot see an exception leaked through `exc_info`.**
`tests/unit/test_managed_pipeline_activation.py:826`
*Why:* the assertion collects `"\n".join(r.getMessage() for r in caplog.records)`. `LogRecord.getMessage()` returns `msg % args` and never renders `exc_info`. I confirmed this empirically: for `log.exception("Background job %s crashed", key)` inside an `except` block whose exception carries a poisoned string, `"sk-live-secret" in record.getMessage()` is `False` while `"sk-live-secret" in logging.Formatter().format(record)` is `True`. The plan requires that injected exception strings reach no log captured at public level; the most likely future regression — someone adds `log.exception(...)` or `exc_info=err` to the managed lane — would pass this test silently. The production code is clean today, so this is a guard gap, not a leak.
*Fix:* build `recorded` from `caplog.text` (formatter-rendered, and it does include the traceback) rather than from `getMessage()`. Apply the same change in `test_a_failure_that_cannot_be_presented_still_reports_nothing_private:949`. Both remain one-line changes.

**3. [minor — coverage] The `reindex` entry point is never exercised for an unsupported source with an actor.**
`tests/unit/test_managed_pipeline_activation.py:264`
*Why:* cell 9's "legacy preparation still runs when an actor is present but the family is unsupported" is proven only through `add_upload`/`run_indexing`. `reindex(ctx, pdf_id, build_actor=actor)` must still reach `_prepare_reindex`; nothing asserts it.
*Fix:* one case asserting `pipeline.reindex(..., build_actor=actor)` on a `.pdf` source calls `_prepare_reindex` and enters the legacy lane.

**4. [minor — presentation] An out-of-range stored `synonymy_threshold` is reported as `operation_failed`, not `invalid_configuration`.**
`src/hippo/ingest/managed_activation.py:202`
*Why:* `build_options` validates `chunk_size_chars`, `chunk_overlap_chars`, `max_upload_bytes`, `max_text_chars` and `openie_workers` and raises `ManagedConfigurationError` for each, but passes `ctx.store.get_settings()["synonymy_threshold"]` straight into `PlainBuildOptions`. If that setting is non-numeric, non-finite or outside `[0, 1]`, `PlainBuildOptions.__post_init__` (`prose_generation.py:100–104`) raises a bare `ValueError("Invalid synonym threshold")`. A bare `ValueError` matches no family in `FAILURES` — `BuildBusy` and `ManagedConfigurationError` are subclasses, not supertypes — so it falls through to `UNKNOWN_CODE = "operation_failed"` with "Check the local logs for this operation", when the operator's actual problem is a setting they can change. No leak, just an unhelpful and inconsistent code.

**7. [minor — evidence accuracy] Deviation 7 overstates `reindex_all` safety.**

**9. [minor — design] Two definitions of "managed" exist in the tree, and the narrower one gates destruction.**
`src/hippo/ingest/managed_activation.py:101` and `src/hippo/store/generations.py:1261` vs `src/hippo/knowledge/build_authority.py:69–78`
*Why:* the brief asked me to look for a second predicate. `managed_eligibility` and `legacy_source_cleanup` both use `source["managed"]` alone. `_source_control`, which decides whether the coordinator treats a build as a bootstrap, uses a strictly broader disjunction: `managed` **or** `active_generation_id` **or** `meta["managed"]` **or** any `Artifact`/`Generation` row naming the source. On a database where they disagree, `plan_dispatch` sends the source to the legacy lane and `legacy_source_cleanup` lets the clear through. **This is not reachable today and is arguably the intended contract** — the plan says artifacts/generations are "a migration consistency check, never a reason to send it to legacy cleanup", and I verified the flag is set atomically with the first artifact write: `_install` (`prose_generation.py:489–501`) calls `store.begin_managed_source` in the same transaction as the `Generation` and `Artifact` puts, and for a bootstrap `_install` runs only inside the publication transaction, so a failed bootstrap leaves neither. Recorded so the divergence is a decision on the record rather than a coincidence, and so a future migration path knows the flag is load-bearing.
*Fix:* none in 3a. A comment at `managed_eligibility` naming `source["managed"]` as the authority and `_source_control` as the deliberately broader guard would stop the next reader from "fixing" one of them.

**10. [minor — efficiency] `present()` opens a locked transaction per extraction callback.**
`src/hippo/ingest/managed_activation.py:271–291`
*Why:* `openie.extract_many` fires `on_progress` once per completed passage, so a build does one `store.transaction()` + `_lock_source` + up to two `get_source` reads + one `update_source` **per passage** — up to 1,000 locked round-trips per managed build. Legacy's progress callback (`pipeline.py:375–377`) is a bare `update_source` with no lock. The lock is not gratuitous — it is what makes the tombstone race safe, and that is the right trade — but it is far more expensive than the legacy equivalent, and nobody has measured it at 1,000 chunks. The Ladybug run (73 cases, 7:55) shows it is fine at test scale.
*Fix:* if it shows up, coalesce — skip the write when only `progress_done` changed and fewer than N passages or M milliseconds have passed since the last one. `present()`'s existing equal-fields short-circuit is the natural place. Not needed for this gate.
