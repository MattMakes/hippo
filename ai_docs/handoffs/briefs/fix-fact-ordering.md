# Brief: deterministic fact order so an unchanged corpus has one view fingerprint on every backend

Read `ai_docs/handoffs/fleet-worker-rules.md` first. Use the worktree recipe with name `factorder` (branch `wp/factorder`, base = the `rag-it-all-tibs` HEAD named in the spawn message).

GOAL: Loading the same unchanged corpus twice yields byte-identical `view_fingerprint` and `GraphIndex.version` on Fake, Ladybug and (by construction) Neo4j, so evaluation-set proofs and saved-answer reuse work on the primary backend. Committed on `wp/factorder`.

CONTEXT:
- Finding: `ai_docs/gates/rag-it-all/task-5-production-activation/evidence-pa4d.md`, section "Open finding: LadybugDB returns extracted facts in an arbitrary order" (read it fully; it has the reproducer and probe results). LadybugDB returns extracted facts in arbitrary order, so `graph.facts` and the derived `fact_vectors` component of the fingerprint payload move between consecutive loads; every other component is stable. Consequences: `EvalAccess._authorized` re-proves a generated set's stored `evidence_fingerprint` and denies; `can_reuse_answer` compares the same value and withholds saved answers. Fake never shows it because its lists keep insertion order.
- Where facts enter the graph: `src/hippo/hipporag/graph_index.py` (`GraphIndex.load`, the fact list and its vectors, `fingerprint_vectors`, `view_fingerprint` in `src/hippo/knowledge/replay.py`), the store loaders (`src/hippo/store/ladybug.py`, `src/hippo/store/base.py`, `tests/fakes/fake_store.py`) and the structural projection (`src/hippo/knowledge/projection.py::_assemble`, which builds facts from retained evidence). Reviewed rule you must not break: the fingerprint uses canonical retained vectors so structural and verified views of the same evidence hash identically (`ai_docs/gates/rag-it-all/task-5-dense-capability/GATES.md`), and legacy-only payloads must stay byte-identical for corpora that were already deterministic (the golden fingerprint test in `tests/unit/test_derived_projection.py::test_original_only_graph_ids_and_fingerprints_are_unchanged` must keep passing unchanged).

DECISION: impose one canonical order at the point where facts (and their vectors, weights and any parallel arrays) are materialised into `GraphIndex`, keyed by the fact's stable identity (its ID, or `(subject, predicate, object, passage ids)` if facts have no ID), not by store return order. Do it in one place that every loader passes through (the `GraphIndex` constructor or a single normalisation helper called by `load`, `_assemble`, `scoped` and `compose_graphs`), so Ladybug, Neo4j and Fake agree by construction. Do not add `ORDER BY` clauses as the only fix. If facts already arrive in a deterministic order on Fake that differs from the canonical order, the golden test tells you: if it breaks, the canonical order must be the order Fake already produced (make Fake's order the definition, and sort others to match).
