# Brief: the legacy synonym pass must never touch managed code rows (R21-B4)

Read `ai_docs/handoffs/fleet-worker-rules.md` first. Use the worktree recipe with name `r21i` (branch `wp/r21i`, base = the `rag-it-all-tibs` HEAD named in the spawn message).

GOAL: Legacy indexing (`add_text`, `add_file`, `add_repo` without an actor, `reindex`, bulk) on an instance that also holds staging or published managed code generations succeeds and never reads, pairs with, or mutates a generation-tagged row; the managed rows are byte-identical after a legacy index. This is R21-B4 of `ai_docs/reports/2026-09-13-code-capture-review.md` (reproduced at function level). Committed on `wp/r21i`.

CONTEXT: `src/hippo/hipporag/indexer.py:250-258` and `:390-391` — the legacy indexer's synonym pass (`find_synonyms`, called by `index_source`) reads EVERY Symbol and DataObject name vector through `store.load_code_embeddings()` (`src/hippo/store/code.py:673-682`, no generation filter), including managed code rows, then writes the pairs through `add_synonyms`. Reproduced by the reviewer: `find_synonyms` returned 3 pairs touching a published managed symbol and `add_synonyms` raised `Sealed native payload or relationship is immutable` (`store/generations.py:1766-1776`); against a staging generation `_assert_generation_writable` refuses instead. So once any repository converts, a never-managed source whose entity names resemble a managed symbol fails to index. This breaks the brief invariant "the legacy lane's behaviour for non-managed sources is byte-identical" (CD1, CD2) and ruling 14 ("only untagged rows serve the legacy lane", `code-capture-notes.md`). The reviewer's scratch reproduction is `/tmp/h21scratch/tests/unit/test_zz_review21_scratch.py::test_zz_t2_legacy_synonym_search_reaches_a_managed_symbol` (read-only; copy its shape). The Ladybug engine defect (`evidence-lbfix.md`): never `IN <list>` on a node string column; scoped reads use `generation_id IS NULL` the way CC2's `untagged=True` read does (`evidence-cc2.md`). Precedent for a lane-restricted store read: `_native_rows(kind, source_id=..., untagged=True)`.

REQUIRED BEHAVIOR:
1. `load_code_embeddings` (or a new untagged variant the indexer switches to; keep the public name if other callers exist and say who they are) returns only rows with `generation_id IS NULL` on every backend (Fake, LadybugDB, Neo4j), in the same order and shape as today for a store with no managed rows (byte-identical legacy behaviour; the existing indexer tests prove it).
2. `find_synonyms`/`add_synonyms` never see a tagged native ID: a RED test through `pipeline.add_text` (and one through `index_source`) on an instance holding a staging generation AND a published code generation whose symbol name vector matches the legacy entity's, on Fake and LadybugDB; after the fix it succeeds, writes no `SYNONYM` edge touching a tagged row, and every managed native row and relation (read through `_native_rows(kind, generation_id=...)` / `_native_relationships(generation_id=...)`) is byte-identical before and after.
3. The reverse guard: a managed build's own synonym or name-vector work (if any, `staged_code`/`code_binding` do not call the legacy pass; verify and say so) does not read untagged legacy rows through this path.
4. Backends: Fake and LadybugDB for the new tests plus `tests/unit/test_hipporag_indexer*.py` (find the real file names with `ls`), `tests/unit/test_ingest_pipeline.py`, `tests/unit/test_converting_source_serving.py`; Neo4j is root-owned: name the new `WHERE n.generation_id IS NULL` shape.
5. Also close, if it is a one-liner in a file you already touch, otherwise leave named in evidence: none of the review's minors name `indexer.py` or `store/code.py`; R21-m20 (`ingest/pipeline.py:504` legacy history warning logs the checkout path and git stderr) belongs to r21c, not you.
