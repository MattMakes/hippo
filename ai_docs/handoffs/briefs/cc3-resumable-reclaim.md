GOAL: A never-published `staging` or `failed` generation can be reclaimed by a new holder without collecting its rows, under every guarantee `claim_generation_build` gives today, so a crashed repository build resumes the same generation instead of restarting from zero. Plan section 8.2 ("Resume") of `ai_docs/plans/rag-it-all-task-5-managed-code-capture.md` as amended by the design review `ai_docs/reports/2026-09-12-code-capture-plan-review.md` B5 and M1; gates CD1 (unchanged results) and CD7 (the reclaim clauses) of `ai_docs/gates/rag-it-all/task-5-code-capture/GATES.md`. CONTEXT: `claim_generation_build` (`src/hippo/store/generations.py:~231-289`) is the fenced admission: source lock, tombstone barrier (`_tombstoned`, `:~217`), future-lease check, the never-published check, live-holder exclusion with the idempotent same-holder return, fence advance, holder install, `attempt_count` carry-over, and — for a `failed` generation — `_collect_generation` (`src/hippo/store/snapshots.py:~263`) before returning it to `staging`. `recover_generation_builds` (`snapshots.py:~346`) marks an abandoned `staging`/`ready` generation `failed`, fails its running job and clears the holder while advancing the fence. `fail_generation_build` (`generations.py:~339`) and `_publish_generation` (`:~1134`) use the three-proof never-published triple (`published_at`, `active_generation_id`, a published `IndexEvent`). `seal_generation` (`:~876`) tolerates a byte-identical existing manifest, which is what makes a crash after the seal recoverable. The prose retry contract is pinned by `tests/unit/test_generation_store.py` (`test_collected_published_generation_never_reopens_for_retry` and neighbours), `tests/unit/test_generation_failure.py` and `tests/unit/test_prose_generation.py`.

REQUIRED BEHAVIOR:
1. `GenerationQueries.reclaim_generation_build(generation_id, *, job_key, lease_owner, lease_expires_at, expected_manifest_hash) -> MaintenanceJob` beside `claim_generation_build`. It performs EVERY step `claim_generation_build` performs, in the same order, EXCEPT `_collect_generation`: source lock; tombstone barrier before the fence advances, before a holder is installed and before anything else is touched; `staging`/`failed` status and a future lease; the FULL never-published triple (`published_at is None`, `source.active_generation_id != gen.id`, no `IndexEvent(kind="published")` for the generation — `claim_generation_build` checks two of the three today; reclaim checks all three, and `claim_generation_build` may be tightened to the triple only if every existing test stays green and you name it in the evidence); live-holder exclusion with the same idempotent same-holder return; fence advance; holder install; `attempt_count` carry-over. A `failed` generation returns to `staging` WITHOUT collection. Factor the shared preamble into one private helper (suggested name `_admit_build(...)`) used by both entry points so the guarantees cannot drift; `claim_generation_build`'s observable behaviour, every existing checksum and every existing test stay byte-identical.
2. `expected_manifest_hash` must equal the stored generation's `manifest_hash`, refusing with a `ValueError` otherwise. Per M1 this is a cheap assertion against a corrupted row, NOT the safety property: `manifest_hash` is in `Generation.identity_fields` so the generation ID already pins it. Say so in the docstring. The real safety properties are the B5 list above plus ruling 10 (derivation versions in generation identity, owned by CC6/CC9) and CC8's absence-asserting probe; do not claim more.
3. A `ready` generation that recovery turned `failed` (crash after the seal, before publication) reclaims to `staging`, and a later identical `seal_generation` succeeds against the byte-identical existing manifest; a `ready` generation still holding a live job is refused as today.
4. Nothing else changes: `claim_generation_build` still collects a `failed` generation (the reviewed prose retry contract), `fail_generation_build` still never collects, `recover_generation_builds` still fails the holder and advances the fence, and `_check_build` accepts the reclaimed job exactly as a claimed one.
5. Tests, NEW `tests/unit/test_generation_resume.py` (the file CD7 names), on Fake and Ladybug: reclaim of a `staging` generation with an expired holder keeps every staged row (knowledge, native, relations, members) and returns a job the writer's `generation_write` accepts; reclaim after `recover_generation_builds` (status `failed`) keeps every row; reclaim of a `ready`-then-`failed` generation then seal with the identical manifest; the five refusals from B5 each refuse WITHOUT advancing `build_fencing_token` and without installing a holder (tombstoned source; live holder from another owner; expired lease; each of the three publication proofs individually); manifest mismatch refuses; same-holder idempotent return; `attempt_count` increments; `claim_generation_build` on the same `failed` generation still collects (contrast test); Ladybug close/reopen between the crash and the reclaim.
