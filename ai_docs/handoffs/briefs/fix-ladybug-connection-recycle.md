# Brief: bound LadybugDB's native per-statement retention by recycling the connection

Read `ai_docs/handoffs/fleet-worker-rules.md` first. Use the worktree recipe with name `lbconn` (branch `wp/lbconn`, base = the `rag-it-all-tibs` HEAD named in the spawn message).

GOAL: A long-running hippo process on LadybugDB has bounded memory: `LadybugStore` recycles its driver connection at safe boundaries so the engine's per-statement native retention can never grow past a configured budget, without changing any result, transaction semantics, lock discipline or checksum. Committed on `wp/lbconn`.

CONTEXT: cc11b's attribution (`ai_docs/gates/rag-it-all/task-5-code-capture/evidence-cc11b.md`, finding "native per-statement retention"; logs `/tmp/hippo-cc11b-retention-cases.log`, `/tmp/hippo-cc11b-conn-probe.out`): under real_ladybug 0.15.3 EVERY `Connection.execute(query, parameters)` call retains ~4.7 KB of native MALLOC_SMALL for the life of the `Connection` (3.8 KB for `RETURN 1`, 1.8 KB for `RETURN $x`, ~4.7–5.1 KB for keyed/WHERE reads, 0 for a literal query with no parameters); `gc.collect()` frees nothing; `Connection.close()` frees most of it. `LadybugStore` holds ONE connection for its lifetime and parameterises nearly every statement, so a managed code build (tens of thousands of statements per minute) grew the live footprint at ~2 GB/min and a 50-file acceptance run peaked at 15.8 GiB of footprint with a 96 MB database. Production inherits it: a hippo server on LadybugDB grows until restart. cc11b also measured whether retention scales with parameter payload size (read its numbers before choosing the budget unit). `src/hippo/store/ladybug.py` (the connection open at `~:270`, `run`, `transaction()`, the lock, `close()`, the buffer-pool setting lbpool added); `src/hippo/config.py` (`ladybug_buffer_pool_bytes` precedent); `tests/unit/test_ladybug_buffer_pool.py` (precedent for driver-kwarg tests); `tests/unit/test_store_ladybug.py`. The Ladybug engine defect (`evidence-lbfix.md`) and the UNWIND helper are unrelated to this one but the same discipline applies.

REQUIRED BEHAVIOR:
1. `LadybugStore` counts parameterised statements (and, if cc11b's payload matrix shows payload scaling, estimated retained bytes) since the connection was opened, and when the count exceeds `Config.ladybug_connection_recycle_statements` (env `HIPPO_LADYBUG_CONNECTION_RECYCLE_STATEMENTS`, default chosen from the measurements so the retained native memory stays under ~256 MiB between recycles; zero or negative refused; document the rule), it closes and reopens the connection AT A SAFE BOUNDARY ONLY: never inside `transaction()` (depth > 0), never while a `QueryResult` is open, and under the store's own lock, so no other thread observes a closed connection. If a recycle is due inside a transaction, it happens right after that transaction commits or rolls back.
2. Semantics unchanged: the same database path, the same `buffer_pool_size`, the same schema state, no re-migration, no lost pending transaction, identical query results before and after a recycle; every existing Ladybug suite passes (`test_managed_source_lifecycle.py`, `test_managed_pipeline_activation.py`, `test_store_ladybug.py`, `test_ladybug_buffer_pool.py`, `test_generation_scoped_reads.py`, `test_query_scoped_reads.py`, `test_code_generation.py -k publish`).
3. Proof: a driver-level test that runs N parameterised statements through `LadybugStore.run` with a small recycle threshold and shows the process footprint (use the same `phys_footprint` reading cc11b used, or the driver's own accounting if available) stays bounded, versus growing without the recycle; a test that a recycle never happens inside `transaction()` (a due recycle inside a transaction is deferred and happens after commit, with the transaction's writes visible afterwards); a test that a due recycle with an open `QueryResult` waits; a concurrency test with the lease-heartbeat pattern (one thread renewing, one thread writing) that never sees a closed-connection error.
4. Evidence: the measured footprint across one CC11 acceptance run at N=8 on LadybugDB (`HIPPO_CODE_ACCEPTANCE_FILES_PER_LANGUAGE=8`, 4 GiB pool, the timings knob) before and after, peak footprint and RSS, and the recycle count; draft an upstream issue text for real_ladybug in the evidence (repro, numbers, versions), do not file it.
