# Adding Go, C# and Rust to hippo's code graph

Written 2026-09-09 against branch `code-graph` at `39e46de`. The branch already parses Python and
TypeScript/JavaScript (plus `.sql` files) into `Symbol` / `DataObject` / `Commit` nodes with
ω-weighted `CODE_EDGE`s (`docs/plans/hippo-for-code/PLAN.md`, deviations table I1–I14). This document

the store, `GraphIndex`, the retriever, the path tools, the pages or MCP changes: a language is a
grammar, a walker, and the resolver rules that bind its names, exactly as `docs/design/README.md` row
"Languages beyond Python, TypeScript/JavaScript and SQL" promises.

## Step 0 — the refactor that makes a language a registration (do first, no behaviour change)

New `src/hippo/codegraph/languages.py`:

```python
@dataclass(frozen=True)
class LanguageRules:
    name: str  # "python" | "typescript" | "go" | "csharp" | "rust"
    walk: Callable[[str, Node, str], FileFacts]
    resolve_module: Callable[[SourceIndex, FileFacts, ImportFact], FileFacts | None]
    scope_defines: Callable[[SourceIndex, FileFacts], dict[str, Symbol]]  # names visible without an import
    module_qualname: Callable[[str], str]
    is_test_path: Callable[[str], bool]
    test_stem: Callable[[str], str | None]  # "orders_test.go" -> "orders"; None = not a test file
    line_comment: str  # "#" or "//"


RULES: dict[str, LanguageRules]  # filled by python.py, typescript.py, go.py, csharp.py, rust.py
```

- `resolve.target_module` becomes `RULES[facts.lang].resolve_module(index, facts, spec)`; the two
  existing bodies move to `python.py` / `typescript.py` untouched. `resolve_imports` seeds
  `bindings` with `scope_defines(...)` **after** the module's own `defines` (own file 1.00 `same_file`
  wins; a same-package/namespace name gets 1.00 `same_scope`, a new provenance string; a `using`/`use`
  binding stays 0.90 `via_import`). For Python and TS `scope_defines` returns `{}`, so their edges are
  byte-identical (the golden `expected.json` test proves it).
- `_tested_by_filename` uses `test_stem` instead of its inline `test_`/`.test.` rule.
- `chunker.LINE_COMMENT` and `extract.WALKERS` read from `RULES`.
- Gate: the whole suite green on all three stores with `expected.json` unchanged before any new walker lands.

## Step 1 — Go (`codegraph/go.py`)

**Module and package.** One module symbol per file, qualname = dotted path without `.go`
(`billing/orders.go` → `billing.orders`, display `billing.orders.Service.Place`). A Go *package* is the
directory: `FileFacts.package = "billing"` (from `package_clause`), and `SourceIndex.scopes[("go", dir)]`
merges every file's top-level defines. `scope_defines` returns that merge minus the file's own.
`module_qualname` keeps `main` and `_test` suffixes as they are.

**Symbols.** `function_declaration` → `function`; `method_declaration` → `method` with qualname
`Receiver.Name` (receiver type = the `receiver` parameter's `type` text with `*` and generics stripped);
`type_declaration > type_spec` whose type is `struct_type` or `interface_type` → `class`
(`is_interface` is not a field; interfaces are classes with no methods of their own, their method
signatures stay in the header passage); `type X = Y`/other type specs → no symbol (header). Nested
functions (`func literal`s) fold into the enclosing symbol. Signature = text from the declaration start
to the `body` start. Doc = contiguous `comment` nodes immediately above (Go convention), first paragraph.
`params` = receiver parameter names + parameter names. `statement_lines` from `block > statement_list`.

**Facts.** `import_declaration > import_spec{name?, path}` → `ImportFact(module=path text, alias=name
or last path segment, name="")`. `call_expression`: `identifier` → bare call; `selector_expression`
→ receiver = `operand` text, name = `field`; a receiver equal to the enclosing method's receiver
variable is rewritten to `self` (so `s.db.Query` → receiver `self.db`, unresolvable chain; `s.Log()` →
`self`). `go`/`defer` statements are calls like any other (`extra.is_await` false). `struct_type >
field_declaration` with a `type` but no `name` → `BaseFact` (embedding). No `RaiseFact`s: Go has no
exceptions; `panic(...)` is an ordinary unresolved call (documented). `LiteralFact` from
`interpreted_string_literal`/`raw_string_literal` inside bodies (SQL, Cypher, Mongo filters).
`AssignFact` from `short_var_declaration`/`var_declaration` whose value is `T{...}` (composite literal)
or `NewT()`/`&T{}` → value `T`.

**Resolution.** `resolve_module`: read `go.mod`'s `module` line once per source (walker of `go.mod` is
a five-line helper in `go.py`, called from `extract_code` when the file is present); an import path
equal to `<module>/<dir>` resolves to any `FileFacts` in `<dir>`; else a proper suffix match on the
directory (like `SourceIndex.by_suffix`, unique or nothing); bare stdlib paths (`fmt`, `errors`) and
third-party paths resolve to nothing → no edge. Because a Go import binds a *package*, `resolve_member`
looks the name up in the package scope, not one file's `defines`: `ledger.Post` → `scopes[("go",
"ledger")]["Post"]`. Bases from embedding → INHERITS 0.90 `resolved` (interface satisfaction is
implicit and gets no edge). OVERRIDES via the existing `_mro_lookup` over embedded structs.
INVOKES tiers: same file 1.00 `same_file`; same package other file 1.00 `same_scope`; through an
import 0.90 `via_import`; else fuzzy 0.50 by the existing rule. TESTED_BY: `_test.go` files, functions
named `Test*`/`Benchmark*`/`Example*`; `test_stem("orders_test.go") = "orders"`; a test in the same
package that mentions a symbol counts as `test_import` 0.85 (the package is the import).

**Data access.** Add to `MONGO_READ`: `Find`, `FindOne`, `Aggregate`, `CountDocuments`, `Distinct`;
`MONGO_WRITE`: `InsertOne`, `InsertMany`, `UpdateOne`, `UpdateMany`, `DeleteOne`, `DeleteMany`,
`ReplaceOne`, `BulkWrite`; marker `call:Collection` with a string argument (`client.Database("x").
Collection("orders").InsertOne`). `db.Query("SELECT …")` / `db.Exec` / `sqlx` / `pgx` all go through the
literal classifier unchanged. Neo4j Go driver `session.Run("MATCH …")` likewise.

**Anchors.** Go panic trace frames: `^\s*(?P<fn>[\w./()*]+)\(.*\)$` followed by
`^\s+(?P<path>\S+\.go):(?P<line>\d+)(?: \+0x[0-9a-f]+)?$` — two lines per frame, innermost first,
`0.8 ** k` decay as today. The `panic: …` header line yields no exception anchor (no RAISES for Go).

## Step 2 — C# (`codegraph/csharp.py`)

**Module, namespace, class.** One module symbol per file (`App/Billing/OrderService.cs` →
`App.Billing.OrderService` as the module qualname; the class inside is `OrderService`, display
`App.Billing.OrderService.OrderService`). Namespaces are the scope: `namespace_declaration` and
`file_scoped_namespace_declaration` set `FileFacts.namespace` for the declarations they contain (a file
with two namespaces records the namespace per top-level type in `FileFacts.namespaces: dict[qualname,
str]`). `SourceIndex.scopes[("csharp", ns)]` merges the types declared in that namespace across files;
`using X.Y;` (`using_directive`) → `ImportFact(module="X.Y", name="", alias="")` binds the whole scope;
`using Alias = X.Y.Type;` → `alias`; `global using` same; `using static X.Y.Type;` binds the type's
static members. `scope_defines` = the file's own namespaces' scopes (visible without `using`).

**Symbols.** `class_declaration`, `struct_declaration`, `record_declaration`, `interface_declaration`,
`enum_declaration` → `class` (nested types `Outer.Inner`); `method_declaration`,
`constructor_declaration`, `destructor_declaration`, `operator_declaration` → `method`;
`local_function_statement` and lambdas fold into the enclosing method; properties, fields, events stay in
the class header passage (no symbol; `property_declaration` accessors with bodies are walked for calls
and attributed to the class symbol). Signature = text from the modifiers to the body / `=>`. Doc = the
`///` comment block above, XML tags stripped, `<summary>` first. `params` from `parameter_list`.

**Facts.** `invocation_expression`: `identifier` → bare; `member_access_expression` → receiver =
`expression` text (`this`, `base`, `Billing`, `s`, `_repo`), name = `name`; `await_expression` sets
`is_await`; `conditional_access_expression` (`x?.Foo()`) reads like member access. `object_creation_
expression` → `CallFact(is_new=True, name=type)` and, inside a local declaration or assignment, an
`AssignFact(target, value=type)`. `base_list` → `BaseFact` per base (class and interfaces alike;
INHERITS 0.90 to whichever resolve, documented as "implements counts as inherits"). `throw_statement >
object_creation_expression` → `RaiseFact("throw")`; `throw;` alone is a re-raise (no fact);
`catch_declaration{type}` → `RaiseFact("catch")`. Literals: `string_literal`, `verbatim_string_literal`,
`interpolated_string_expression` (holes → `?`), `raw_string_literal`. `[Fact]`, `[Test]`, `[TestMethod]`,
`[Theory]`, `[TestCase]` attributes on a method → `is_test`; paths under `test/`, `tests/`, `*.Tests/`,
files `*Tests.cs`/`*Test.cs` → test files (`test_stem("OrderServiceTests.cs") = "OrderService"`).

**Resolution.** `resolve_module` for a `using`: the namespace scope (a *scope*, not a file — return a
synthetic `FileFacts`-shaped view, or extend `Resolution` with `scope: dict[str, Symbol]`; pick the
second, it is one optional field). Static calls `Billing.Total(o)`: receiver `Billing` resolves to a
class through the bindings (`using` or same namespace) → `_on_class`. `this` and `base` are already
`SELF_NAMES`/`SUPER_NAMES` (add `base`). `var s = new OrderService(); s.Place(o)` is the existing
`AssignFact` → `_receiver_type` path. Generic types strip `<...>` before lookup. Extension methods,
DI-injected interfaces (`_service.Place()` where `_service` is a field typed `IOrderService`) resolve
by the field's declared type when the walker records field declarations as `AssignFact(scope=class,
target=field name, value=type)` — cheap and the common ASP.NET shape; note it in the docs.
Partial classes: symbols carry the same qualname in two files, so `symbol_id` (path-namespaced) keeps
them distinct and `scopes[ns]` lists the first seen; CONTAINS from each file's module.

**Data access.** `MONGO_*` PascalCase names as for Go (`InsertOneAsync`/`FindAsync` etc. too: strip a
trailing `Async` before the lookup); marker `call:GetCollection` with a string argument. EF Core
`_db.Orders` DbSets are **not** resolved (no literal names it; documented). Dapper/ADO SQL strings and
Neo4j `session.RunAsync("MATCH …")` go through the classifier.

**Anchors.** .NET trace frames: `^\s*at (?P<fn>[\w.<>`,\[\]]+)\((?:[^)]*)\)(?: in (?P<path>[^:]+\.cs):line (?P<line>\d+))?$`;
the header `Unhandled exception. System.X: msg` / `X: msg` yields an exception anchor (RAISES exists
for C#). Frames innermost first, `0.8 ** k`.

## Step 3 — Rust (`codegraph/rust.py`)

**Module tree.** Rust modules are files plus `mod.rs`/`lib.rs`/`main.rs` plus inline `mod x { }`.
Module qualname = dotted path without `.rs`, keeping `mod`/`lib`/`main` the way Python keeps `__init__`
(`src/billing/mod.rs` → `src.billing.mod`; `package_of` learns that a trailing `.mod`, `.lib` or
`.main` names the directory). `crate::` resolves to the directory holding `lib.rs` or `main.rs`
(first found, recorded once per source, like `go.mod`); `super::` walks one directory up (from a
`mod.rs` the *parent* directory, from `x.rs` the directory of `x`); `self::` is the current module.
`mod x;` declarations are `ImportFact(module="self::x", name="", alias="x")`. Inline `mod tests { … }`
becomes a symbol of kind `module` with qualname `tests` (owner logic in `build_index` and
`extract._contains` handles any kind as an owner; `python._is_member`'s equivalent in `rust.py` must
accept `module` as a container).

**Symbols.** `struct_item`, `enum_item`, `union_item`, `trait_item` → `class`; `function_item` at
module level → `function`; inside `impl_item` → `method` with qualname `Type.name` (the `type` field
with generics stripped; `impl Trait for Type` attaches to `Type` and emits `BaseFact(Type, Trait)`);
inside a `trait_item` body → `method` `Trait.name` (default or required); `type_item`, `const_item`,
`static_item`, `macro_definition` stay in the header. Closures fold. Signature = text up to the body.
Doc = `///` (`outer_doc_comment_marker`) lines above; `//!` at file top = module doc. `params` from
`parameters` (skip `self`). `#[test]` → `is_test`; files under `tests/`, `benches/`, and any symbol
inside a `#[cfg(test)]` mod are tests (`test_stem` = the crate-level `tests/<name>.rs` name).

**Facts.** `use_declaration`: `scoped_identifier` → `ImportFact(module=path, name=name, alias=name)`;
`scoped_use_list` expands each entry (`{total, send_invoice as invoice}` → two facts; `use_as_clause`
gives the alias; `self` inside a list imports the module itself); `use x::*` → wildcard. Calls:
`call_expression{function: identifier}` → bare; `scoped_identifier` → receiver = path text (`ledger`,
`S`, `Self`, `crate::ledger`), name = `name`; `field_expression` → receiver = `value` text (`self`,
`s`), name = `field`; `macro_invocation` is never a call. `let_declaration` whose value is
`Type::new(...)`/`Type { … }`/`Type::from(...)` → `AssignFact(target, value=Type)`. `try_expression`
is transparent. RaiseFact: from the function's return type only — `-> Result<_, E>` where `E` is a
type identifier → `RaiseFact("raise", E)` (no line; use the signature line); `?` and `Err(...)` produce
nothing; `match … Err(E::…)` produces no `catch` (documented: Rust has values, not exceptions).

**Resolution.** `resolve_module` handles `crate::`, `super::`, `self::` chains and sibling `mod x;`; a
path whose head is neither (external crate) → no edge. `Self::helper()` → `SELF_NAMES` gains `Self`.
`S::new()` → `_on_class`. Trait impls: `BaseFact(S, T)` → INHERITS 0.90 `resolved`; a method
`S.name` whose trait `T` declares `name` → OVERRIDES 0.90 `mro` through the existing pass (the trait's
required method is a `Trait.name` symbol, so `_mro_lookup` finds it). A method in `impl S` in another
file than `struct S` is a member of `S` across files: `index.members` is keyed by `(path, class)`, so
`_on_class` for Rust must also try the path where `S` is defined — extend `_on_class` to consult
`RULES[lang].member_paths(index, qualname)` (Rust: every path with an `impl` for that type; others:
the one path). Same-crate INVOKES through `use` is 0.90 `via_import`; same file 1.00.

**Data access.** `sqlx::query("SELECT …")`, `diesel::sql_query`, `client.query("…")` are literals;
`mongodb` crate uses snake_case names already in the sets; `collection::<T>("orders")` marker
`call:collection`. Neo4j `neo4rs::query("MATCH …")` is a literal.

**Anchors.** `thread '(?P<thread>[^']+)' panicked at (?P<path>\S+\.rs):(?P<line>\d+):\d+` and
backtrace frames `^\s*\d+: (?P<fn>\S+)$` followed by `^\s+at (?P<path>\S+\.rs):(?P<line>\d+)(?::\d+)?$`
(RUST_BACKTRACE=1). The panic line is frame 0.

## Decisions taken here (flag if you disagree)

- **Same-package / same-namespace calls get ω 1.00 with provenance `same_scope`.** Go and C# resolve
  these unambiguously; 0.90 `via_import` would understate it, and 1.00 keeps the ω table's tiers.
- **Interface implementation counts as INHERITS** (C# `base_list`, Rust `impl T for S`); Go interface
  satisfaction is implicit and gets no edge.
- **No RAISES/CATCHES for Go**; Rust RAISES only from `-> Result<_, E>` return types; C# gets both from
  `throw`/`catch`.
- **`tools/build.go` stops being the unparsed-code fixture** (it becomes parsed); `tools/build.rb` takes
  the role. Ruby stays unsupported.
- **No LSP** (`gopls`, OmniSharp, `rust-analyzer`) in this pass: the same phase-2 adapter slot as
  pyright/tsserver (PLAN.md D23).
- **Go `_test.go` in the same package is `test_import` 0.85**, since the package is the import.

## Out of scope

Java/Kotlin/C/C++ (the same recipe, not requested); generics-aware resolution; C# extension methods
and EF DbSets; Rust trait objects (`dyn T`) and generic bounds as call targets; Go interface
satisfaction edges; CCG slices for the new languages (deferred for all languages, PLAN.md D12).
