# Code as a first-class data type in hippo (phase 1)

## Context

hippo is a portable HippoRAG: text → passages → OpenIE (entities + facts) → graph in LadybugDB or Neo4j → in-memory igraph → Personalized PageRank (PPR) → ranked passages → LLM answer. Code already gets in (repos, zips, files) but is treated as prose: line-window chunks and NER + triples over every window. That is slow on a local model, noisy (OpenIE over code is where HippoRAG's known noise problem enters) and blind to the one thing code has that prose does not: exact structure.

The research synthesis in the request (GraphCoder, CodexGraph, RepoGraph, GRACE, the RACG survey, LARGER, DyRetriever) converges on: a symbol-level global graph (Module/Class/Function + Contain/Import/Invoke/Inherit), provenance-weighted edges (ω), lexical **and** dense seeding, bounded multi-seed expansion (which PPR already is), no LLM-authored graph queries, and structure delivered *with* the retrieval result as typed triples. HippoRAG's PPR over a heterogeneous node×passage graph is the right spine: ω becomes the transition weight, node specificity damps hub symbols, synonym edges bridge prose concepts to identifiers.

**User decisions (2026-09-07), reconciled with the "Code-Only HippoRAG: Design v1.0" doc:**
- Corpus: **source code repositories and nothing else**: source files, tests, in-repo docs (README, docstrings, comments) and **git history**. PRDs, tickets, external DDL and monitors are out.
- Code graph: tree-sitter Python + TypeScript/JavaScript symbols with CONTAINS / IMPORTS / INVOKES / INHERITS / OVERRIDES / RAISES / CATCHES / TESTED_BY, each with a provenance ω. INVOKES carries `call_line`, `in_branch`, `arg_binding`.
- **Data-access edges are kept** (asked for explicitly): READS/WRITES from SQL, MongoDB and Cypher literals *inside the repo's own files* and from in-repo `.sql` files. That is still "source code only"; only external DDL ingestion is out.
- **Git history in phase 1, bounded**: `Commit` nodes, `MODIFIES` (diff hunks ∩ symbol ranges), `PRECEDES`, commit-message passages, a configurable history depth (default 200 first-parent commits), and a commit-based localization eval.
- **LLM helpfulness pass on by default** (DyRetriever "select": keep / drop / expand-once), behind a setting so evals can compare.
- Communities: Leiden on the file-level projection, stored on symbols, shown as the subsystem label, +10% rerank prior.
- OpenIE: prose only (design doc §4.4 step 5; the survey and LARGER run no LLM extraction over code): a symbol's docstring/doc-comment when ≥ 80 chars, README/markdown, commit messages. Never function bodies or DDL.
- Passage granularity: one passage per symbol (module header, class header, each function/method), titled `path :: qualname (lines a-b)`; long bodies split at top-level statements of the body.
- **Deferred with reasons**: CCG slice artifacts (the statement-split passages bound prompt cost for now); pyright/tsserver LSP resolvers (heavy deps; the in-house resolver gives the 0.90 tier, LSP is a later drop-in adapter); intent classification with typed restart; `Field` nodes and READS/WRITES_FIELD; `Repo`/`Directory` nodes; commit-aware incremental re-indexing (sources are still re-indexed wholesale, so "incremental" means the extractor is per-file and cached, not that the graph is patched).

**Verified on this machine** (scratch venv): `tree-sitter` 0.26, `tree-sitter-python` 0.25 (ABI 15), `tree-sitter-typescript` 0.23.2 (exposes `language_typescript()` and `language_tsx()`; the tsx grammar parses plain JS/JSX cleanly), `sqlglot` 30 (`parse_one(..., error_level=IGNORE)`; `find_all(exp.Table)` gives read/written tables). tree-sitter parses all of hippo's Python in 55 ms. On LadybugDB 0.15.3: `ALTER TABLE <rel> ADD IF NOT EXISTS FROM A TO B` works and is idempotent (in memory; must be re-verified on a closed-and-reopened file, first test in WP1); `CREATE` of a rel bound by a multi-label node pattern is refused (writes go one statement per concrete label pair); `NOT EXISTS {}` under `UNWIND` does not see rows created in the same statement (dedupe in Python); `SET a = CASE.., b = CASE..` is sequential (compute a `better` flag in a `WITH` first); a `None` in a bytes column under `UNWIND` breaks `decode()` (always `text(x or "")`).

## Design summary

```
Existing:  (Source)<-[:FROM]-(Passage)-[:MENTIONS]->(Entity)   (Passage)-[:STATES]->(Fact)-[:SUBJECT|OBJECT]->(Entity)
           (Entity)-[:SYNONYM {score}]-(Entity)   (Entity|Passage)-[:TUNED {weight}]-(Entity|Passage)
Added:     (Symbol {source_id, kind: module|class|function, qualname, path, lines, signature, doc, is_test, raises[], community, boost, embedding})
           (DataObject {source_id, kind: table|column|collection|label|rel_type, qualname, dialect, embedding})
           (Commit {source_id, sha, author, date, message})
           (Symbol|DataObject)-[:CODE_EDGE {kind, omega, provenance, extra}]->(Symbol|DataObject)   directed
           (Commit)-[:MODIFIES {omega, hunk}]->(Symbol)        (Commit)-[:PRECEDES]->(Commit)   first-parent order
           (Symbol|DataObject|Commit)-[:DEFINED_IN]->(Passage)                                   ω 1.0
           (Passage)-[:REFERS_TO {omega, token}]->(Symbol|DataObject)   prose (README, docstring, commit) naming a symbol
           SYNONYM now joins Entity|Symbol|DataObject in any combination; TUNED adds Symbol|DataObject
```

| Edge kind | ω | provenance (stored verbatim) |
|---|---|---|
| CONTAINS (module→class/function, class→method, table→column) | 1.00 | `syntax` |
| IMPORTS (module → imported module/member) | 0.95 direct path / 0.90 through `__init__` or index re-export / 0.60 wildcard | `import_path` / `reexport` / `wildcard` |
| INHERITS | 0.90 resolved / 0.50 unique bare-name match | `resolved` / `fuzzy_name` |
| OVERRIDES (method → same-named method in a resolved base) | 0.90 | `mro` |
| INVOKES | 1.00 same file / 0.90 via import or inheritance / 0.50 unique bare-name match | `same_file` / `via_import` / `via_inheritance` / `fuzzy_name`; `extra` JSON: `{call_line, in_branch, is_await, arg_binding}` |
| RAISES / CATCHES (function → in-repo exception class) | 0.90 resolved | `resolved`; builtin exception names go to `Symbol.raises[]`, not an edge |
| TESTED_BY (symbol → test function) | 0.85 test imports it / 0.75 test file mirrors the module name / 0.60 name appears in the test body | `test_import` / `test_filename` / `test_mention` |
| READS / WRITES (symbol → data object) | 0.85 parsed literal / 0.60 bare identifier | `sql_literal`, `mongo_chain`, `mongoose_model`, `cypher_literal` / `bare_identifier` |
| MODIFIES (commit → symbol) | 1.00 hunk ∩ symbol range | `hunk` (JSON: file, old/new ranges, churn) |
| REFERS_TO (prose passage → symbol/data object) | 0.85 backticked or qualified name / 0.60 split-token match | `backtick` / `tokens` |

Calls to anything that does not resolve inside the source (stdlib, third-party, `print`, `console.log`) produce **no edge**. No cross-source edges in phase 1; symbols and commits belong to their source (deleted with it, visible with it, never orphan-swept). `in_branch` is true when the call sits under an `if`/`elif`/`else`/`try`/`except`/loop/conditional expression in the caller; `arg_binding` maps callee parameter names (from its signature) to the caller's argument expressions, positional then keyword, truncated to 60 chars each. One CODE_EDGE per `(a, b, kind)`: repeated call sites keep the highest ω and the first `call_line`, with `extra.call_lines` listing the rest.

**PPR** stays in-process, undirected igraph, byte-identical call (fidelity). Edge weight rule becomes `tuned if set else max(fact_count, 1.0 if mention, synonym_score, ω_max)`; consequence (goes in FIDELITY.md): an entity pair with three facts (3.0) outranks any code edge. Direction is kept only in a side structure for the path tools. **Node specificity** for code nodes = `1 / (incoming INVOKES/READS/WRITES + 1)` instead of `1 / passages` (MODIFIES excluded so churn does not silence the symbols people ask about). **Seeding** adds lexical anchors (identifiers, stack-trace frames with 0.8 decay per frame outward, fenced code, diff hunks) and up to N dense hits on code passages, in parallel with the fact-filter seeds; symbol seeds bypass the fact filter and `linking_top_k`. **Communities** (Leiden) give a +10% rerank prior to passages in a seed's community. **Select pass**: one LLM call over the top passages returns keep / drop / expand; "expand" fetches one hop of INVOKES/OVERRIDES/RAISES neighbours (≤ 10, ω ≥ 0.75) summarised one line each, never bodies. **Answering** prepends one `Title: Code graph` pseudo-passage (typed triples with `in_branch`/`arg_binding`, tests, last commits) to the unchanged `rag_qa` prompt. **Four fixed tools**, `explain_path(a, b)`, `blast_radius(symbol)`, `exception_path(symbol, exception)` and `history(symbol)`, computed in-process; no LLM-written Cypher.

**Reconciled interface decisions** (the three layer designs differed; these win):
- Ids: `symbol_id(source_id, path, qualname) = make_id("symbol-", f"{source_id}:{path}:{qualname}")`, `data_id(source_id, kind, qualname) = make_id("data-", f"{source_id}:{kind}:{qualname}")`, defined in `codegraph/model.py`; the store never computes ids.
- **One vector per symbol/data object**: `embedding` = the *name text* (`"order service OrderService"`, i.e. split tokens + original spelling), used only for synonym search. Dense seeding at retrieval time uses the defining passage's embedding, so no descriptive symbol vector is needed.
- `split_identifier(name) -> list[str]` lives in `hipporag/text.py` (`OrderService → [order, service]`, `get_user2 → [get, user, 2]`, `pkg.HTTPServer → [pkg, http, server]`); codegraph, store and anchors all use it.
- In-memory names: `GraphIndex.code_nodes: dict[str, CodeNode]`, `code_out/code_in: dict[int, list[CodeEdge]]`, `specificity` (alias property `entity_passage_count`), `name_index`, `out_edges(v)`, `in_edges(v)`, `defining_passages(v)`, `symbols_defined_in(passage_v)`.
- Store keeps `get_symbols` / `get_data_objects` (access-scoped) but **no** `search_symbols`: name lookup for anchors, pickers and the tools runs on the in-memory `name_index` of the caller's scoped index.
- One test fixture tree, `tests/fixtures/code_sample/` (WP2 §2.7), shared by every layer.

## Work packages

Dependencies: WP1 (store + index) ← WP2 (extractors, chunker, indexer; WP2b = git history) ← WP3 (retrieval, select pass, tools) ← WP4 (surfaces, evals, docs). ## WP1 — Store (LadybugDB, Neo4j, FakeStore) and `GraphIndex`

### 1.1 Shared module `src/hippo/store/code.py`
Constants `SYMBOL_KINDS`, `DATA_KINDS`, `CODE_EDGE_KINDS = ("CONTAINS","IMPORTS","INHERITS","OVERRIDES","INVOKES","RAISES","CATCHES","TESTED_BY","READS","WRITES")`, `SPECIFICITY_KINDS = ("INVOKES","READS","WRITES")` (MODIFIES deliberately excluded), `CODE_EDGE_PAIRS = {(Symbol,Symbol),(Symbol,DataObject),(DataObject,DataObject)}`; row shapers `_symbol_row` / `_data_object_row` / `_commit_row` (defaults like `_passage_row` in `store/memory.py`; `doc ""` → `None`); the Neo4j `CodeQueries` mixin (added to `Store`'s bases in `store/__init__.py`).

### 1.2 Schema
- `store/ladybug.py` `NODE_TABLES`:
  - `Symbol`: `id STRING PRIMARY KEY, name STRING, qualname STRING, kind STRING, lang STRING, path STRING, line_start INT64, line_end INT64, signature STRING, doc STRING, is_test BOOLEAN, raises STRING[], community INT64, source_id STRING, name_tokens STRING[], boost DOUBLE, embedding FLOAT[], created_at STRING`
  - `DataObject`: `id STRING PRIMARY KEY, name STRING, qualname STRING, kind STRING, dialect STRING, source_id STRING, name_tokens STRING[], boost DOUBLE, embedding FLOAT[], created_at STRING`
  - `Commit`: `id STRING PRIMARY KEY, sha STRING, author STRING, date STRING, message STRING, source_id STRING, ordinal INT64, created_at STRING` (`ordinal` = position in first-parent order, newest 0; id = `make_id("commit-", f"{source_id}:{sha}")`)
  - Rel tables: `CODE_EDGE` gains `extra STRING` (JSON text through `text()`/`decode`); new `MODIFIES` (`FROM Commit TO Symbol`, `omega DOUBLE, hunk STRING`), `PRECEDES` (`FROM Commit TO Commit`), `REFERS_TO` (`FROM Passage TO Symbol, FROM Passage TO DataObject`, `omega DOUBLE, token STRING`); `DEFINED_IN` adds `FROM Commit TO Passage`.
  - `boost` exists so `set_node_boost` (changesets) works on code ids: widen it to `MATCH (n:Entity|Symbol|DataObject {id: $id}) SET n.boost = $boost` on Neo4j and to a `_labels_of`-resolved label on LadybugDB; FakeStore widens its known set. `load_symbols`/`load_data_objects` return `boost` (default 1.0) and `GraphIndex.load` puts it in the boost array. Without this a saved changeset boosting a symbol would work in simulation and silently do nothing when applied.
- `REL_TABLES` becomes `(name, [pair, ...], extra)`: `SYNONYM` = all 9 ordered pairs over `(Entity, Symbol, DataObject)`; `TUNED` = all 16 over `(Entity, Passage, Symbol, DataObject)`; new `CODE_EDGE` (`FROM Symbol TO Symbol, FROM Symbol TO DataObject, FROM DataObject TO DataObject`, `kind STRING, omega DOUBLE, provenance STRING, extra STRING`); new `DEFINED_IN` (`FROM Symbol TO Passage, FROM DataObject TO Passage, FROM Commit TO Passage`); `MODIFIES`, `PRECEDES`, `REFERS_TO` as above. `ensure_schema` runs `CREATE REL TABLE IF NOT EXISTS` then `ALTER TABLE <name> ADD IF NOT EXISTS <pair>` for every pair (grows old files in place). `INT_FIELDS += {line_start, line_end}`, `FLOAT_FIELDS += {omega}`.
  - **Contingency** if the ALTER does not survive close/reopen on a file (test 1.7a): one-time rebuild gated by `get_meta("schema_version")`: `ALTER TABLE SYNONYM RENAME TO SYNONYM_OLD` → create the wide table → copy rows → `DROP TABLE SYNONYM_OLD`; same for TUNED (RENAME/DROP verified).
- `store/base.py` `CONSTRAINTS`: unique `Symbol.id`, `DataObject.id`, `Commit.id`; range indexes on `Symbol.source_id`, `DataObject.source_id`, `Commit.source_id`.
- FakeStore: `symbols`, `data_objects`, `commits: dict[str, dict]`, `code_edges: dict[(a,b,kind), {omega, provenance, extra}]`, `definitions: set[(node_id, passage_id)]`, `modifies: dict[(commit_id, symbol_id), {omega, hunk}]`, `precedes: set[(a, b)]`, `refers_to: dict[(passage_id, node_id), {omega, token}]`.
- Access: symbols/data objects carry `source_id`; every access-taking read does `MATCH (s:Source {id: n.source_id}) WHERE {ACCESS_WHERE}` (a property, not a FROM rel: one-statement deletion, no second join path).

### 1.3 Methods (identical names/row shapes on all three stores; LadybugDB wraps free text with `text(x or "")` / `decode()`)
- `add_symbols(rows)`: `{id, source_id, name, qualname, kind, lang, path, line_start, line_end, signature, doc, embedding}`; MERGE by id, updates in place, `created_at` on create, store fills `name_tokens = split_identifier(name)`; rows whose source is missing are skipped. `add_data_objects(rows)`: `{id, source_id, name, qualname, kind, dialect, embedding}`.
- `add_code_edges(rows)`: `{a, b, kind, omega, provenance, extra: dict}` (`extra` stored as JSON text, merged on re-add by keeping the higher-ω row's value); directed; Python prelude dedupes to the best ω per `(a, b, kind)`, drops self-loops, raises `ValueError` on unknown kind; re-adding raises ω (then replaces provenance), never lowers. LadybugDB: resolve labels with `_labels_of(ids)` (`MATCH (n:Entity:Passage:Symbol:DataObject) WHERE n.id IN $ids RETURN n.id, label(n)`), group by label pair, two statements per group (update half with a `WITH ..., (r.omega IS NULL OR r.omega < row.omega) AS better`; create half with `WHERE NOT EXISTS { MATCH (a)-[r:CODE_EDGE]->(b) WHERE r.kind = row.kind }`). Neo4j: `MATCH (a:Symbol|DataObject {id: row.a}), (b:Symbol|DataObject {id: row.b}) WHERE NOT (a:DataObject AND b:Symbol) MERGE (a)-[r:CODE_EDGE {kind: row.kind}]->(b) ON CREATE SET ... ON MATCH SET r.provenance = CASE..., r.omega = CASE...` (provenance first).
- `link_definitions(pairs)`: `(node_id, passage_id)` → DEFINED_IN via the existing `_link` per label / Neo4j MERGE.
- `get_symbols(ids, access=None)` / `get_data_objects(ids, access=None)`: rows plus `source_name` and `passage_ids` (from DEFINED_IN), asked order, visible iff source visible.
- Loaders (unrestricted, feed `GraphIndex.load`): `load_symbols()` → `{id, name, qualname, kind, lang, path, line_start, source_id, source_name, in_degree, created_at}` with raw `in_degree` = incoming CODE_EDGE of `SPECIFICITY_KINDS` (LadybugDB `OPTIONAL MATCH (n)<-[r:CODE_EDGE]-() WHERE r.kind IN $kinds ... count(r)`; Neo4j `count { ... }`); `load_data_objects()` likewise with `dialect`; `load_code_edges()` → `{a, b, kind, omega, provenance}`; `load_definitions()` → `{node_id, passage_id}`; `load_code_embeddings()` → `(ids, vectors)` over Symbol and DataObject.
- Commits: `add_commits(rows)` (`{id, source_id, sha, author, date, message, ordinal}`), `add_modifies(rows)` (`{commit_id, symbol_id, omega, hunk}`), `add_precedes(pairs)`, `add_refers_to(rows)` (`{passage_id, node_id, omega, token}`), `set_symbol_communities(mapping)`, `get_commits(ids, access)`, `load_commits()` (`{id, sha, author, date, message, source_id, ordinal}`), `load_modifies()`, `load_precedes()`, `load_refers_to()`. `load_symbols` also returns `is_test`, `raises`, `community`. `in_degree` counts INVOKES/READS/WRITES only, **not** MODIFIES: a function changed in 150 of 200 commits would otherwise get specificity 1/151 and a stack-trace anchor on it would be crushed; churn correlates with where the bugs are.
- `stats()` adds `symbols`, `data_objects`, `code_edges`, `commits`.
- `delete_source` and `delete_passages_for_source` first run `MATCH (n:Symbol:DataObject:Commit) WHERE n.source_id = $id DETACH DELETE n` (Neo4j batched `WITH n LIMIT 500`); FakeStore prunes `code_edges`, `definitions`, `modifies`, `precedes`, `refers_to`, `synonyms`, `tuned` by hand. `remove_orphans` is unchanged (never sweeps code nodes or commits).
- SYNONYM/TUNED widening: `add_synonyms` and `set_edge_weight`/`clear_edge_weight` accept ids of any named kind. LadybugDB: `_labels_of` replaces `_node_label`; update half is one multi-label statement, create half per label pair; `load_synonyms` drops the `:Entity` labels. Neo4j: `Entity|Symbol|DataObject` / `Entity|Passage|Symbol|DataObject` disjunctions in `memory.py` and `changesets.py`. FakeStore: widen the `known` sets. `analysis/changesets.py` needs no change to apply ops on code ids.

### 1.4 `GraphIndex` (`src/hippo/hipporag/graph_index.py`)
- Constants `SYMBOL = "symbol"`, `DATA = "data"`, `COMMIT = "commit"`, `CODE = (SYMBOL, DATA, COMMIT)`, `DEFINED_IN = "DEFINED_IN"`. Vertex order: **entities, symbols, data objects, commits, passages**. `num_entities = len(entity_names)`; `first_passage_vertex = num_entities + len(code_nodes)`; `passage_position(v) = v - first_passage_vertex`.
- `CodeNode(id, node_kind, name, qualname, kind, source_id, source_name, lang, path, line_start, line_end, signature, doc, dialect, boost, is_test, raises, community, sha, date, ordinal)` (commits use `qualname = sha[:10] + " " + first message line`); `DirectedEdge(src, dst, kind, omega, provenance, extra: dict)` (named differently from `codegraph.model.CodeEdge`, which WP3 imports side by side). MODIFIES, PRECEDES and REFERS_TO rows become `DirectedEdge`s of those kinds so one structure serves every path tool.
- `Edge` gains `omega: float = 0.0` (max over code edges either direction; DEFINED_IN counts 1.0) and `code_kinds: list[str]`; `weight` adds `omega` to the max; `kinds` appends lowercased code kinds (`"invokes"`, `"defined_in"`, `"modifies"`, `"refers_to"`, …).
- Communities are computed by the **indexer** post-pass (WP2 §2.4), not at load time: `igraph.Graph.community_leiden(objective_function="modularity", weights=count × ω)` over the source's file-level projection of IMPORTS/INVOKES/INHERITS (modules as vertices), label = `f"{source_id[:6]}:{cluster}"` hashed to an int, written to `Symbol.community` (data objects inherit the community of their heaviest READS/WRITES neighbour). The index only loads it: `CodeNode.community`, `GraphIndex.community_of(v)`, and `community_name(c)` = the most-connected module's directory name (the "subsystem" label in answers).
- New fields: `code_nodes`, `code_vertices`, `code_out`, `code_in` (DEFINED_IN edges are included with kind `DEFINED_IN`; path tools skip them), `name_index: dict[str, list[str]]` (lowercase `name`, lowercase `qualname`, and each split token → node ids; symbols and data objects; **shared, not rebuilt, by `scoped()`**: every consumer filters hits through the scoped `idx_of`, which is what keeps hidden symbols out), `specificity` (entities: mention count; code: `in_degree + 1`; passages 0) with `entity_passage_count` as an alias property so `retriever.py` and `routes/graph.py` keep working until WP3/WP4 update them. `entity_boost` is loaded for code nodes too (from their `boost` column), so boosts saved by a changeset apply to symbols exactly as to entities.
- New methods: `code_node_by_id`, `out_edges(v)`, `in_edges(v)`, `defining_passages(v)`, `symbols_defined_in(passage_v)`, `name_of` returns `qualname` for symbols and `"<kind> <qualname>"` for data objects.
- `load()`: eight more queries (symbols, data objects, commits, code edges, definitions, modifies, precedes, refers_to); DEFINED_IN feeds `Edge` at ω 1.0 (the only PPR path from a symbol to text); MODIFIES and REFERS_TO feed `Edge` with their ω (that is how commit passages get retrieved); **PRECEDES stays out of `Edge`/igraph** (200 commits would otherwise chain every symbol they touched into one undirected neighbourhood) and exists only as `DirectedEdge`s for the `history` tool.
- `scoped()`: code nodes kept iff `source_id` visible; edge carry-over must copy `omega` and `code_kinds`; `code_out/code_in` remapped and pruned; code specificity recomputed from surviving in-edges; early `return self` only when both all passages and all code nodes are kept. `graph_with_edits` unchanged (copies via `vars`).

### 3.1 Settings (`store/base.py` DEFAULT_SETTINGS + SETTING_RULES; settings page help text in `web/routes/pages.py`; `templates/settings.html` inputs must take `min/max` from `SETTING_RULES` because today's hard-coded `max="1"` would make `code_seed_weight` unsaveable)
`code_seed_weight` 1.0 (float 0–10; 0 = ignore symbols named in the question), `code_theta` 0.5 (float 0–1; min ω for path tools and the answer block), `code_dense_seeds` 5 (int 0–20; code passages similar to the question that also seed their symbol), `code_triples_chars` 1500 (int 0–8000; size cap of the Code graph block), `code_community_boost` 0.1 (float 0–1; score bonus for passages in a seed symbol's community), `code_select` True (bool; the LLM keep/drop/expand pass over the top passages when code seeds fired), `code_expand_max` 10 (int 0–20; neighbours fetched per "expand", ω ≥ 0.75).

### 3.2 `src/hippo/hipporag/anchors.py` (pure, no LLM)
`find_anchors(question, index) -> list[Anchor(node_id, vertex, token, how, kind)]`, `how ∈ identifier | stack_trace | exception | fenced_code | diff`, deterministic order, `MAX_ANCHORS = 20`, `MAX_MATCHES_PER_TOKEN = 8`:
1. Stack traces: `File "(path)", line N(, in fn)?` and `path.ext:N` (also `at fn (path:N:M)` for Node); path matched by equality or suffix against `code_nodes[*].path`; innermost symbol whose range contains N; on line drift fall back to the symbol named `fn` on that path. Frames are ordered innermost first and carry `frame_weight = 0.8 ** k` (k = 0 for the innermost). The trailing `SomeError: message` line yields an exception anchor: symbols whose `raises[]` contains the name, and in-repo classes of that name (`how="exception"`, weight 0.8).
2. Fenced code blocks: regex identifier tokens (`[A-Za-z_]\w*(\.[A-Za-z_]\w*)*`), minus Python/JS keywords, split-token matching allowed. A block that looks like a unified diff (`@@ -a,b +c,d @@` and `+++ b/path`) is handled as a diff: hunk new-side ranges → symbols on that path by range (`how="diff"`, weight 1.0), and `+`/`-` line identifiers as fenced tokens.
3. Inline: backticked/quoted → as fenced; dotted `a.b.c` → qualname equal or `endswith("." + tok)` (data objects also match `schema.table`); snake_case / camelCase → exact name or qualname suffix; **bare words** only when ≥ 3 chars, ∉ STOPWORDS ∪ COMMON_WORDS (`get, set, list, post, run, test, main, data, value, name, type, user, id, key, …`) and a hit has `name.lower() == tok` (never a split-token hit).
Every hit is filtered through the given index's `idx_of` and `node_kind ∈ {symbol, data}`, so a scoped index can never surface a hidden symbol; per token sorted by `(specificity asc, qualname)`. `Anchor.weight` follows the code-only design: exact identifier / fenced / diff 1.0, stack frame `0.8 ** k`, exception 0.8, split-token match 0.6.

### 3.3 `src/hippo/hipporag/paths.py`
`resolve_symbol(index, name_or_id) -> vertex` (id → exact qualname (ci) → exact name; several → `AmbiguousSymbol(candidates=[{id, qualname, kind, path}])`, none → `UnknownSymbol`); `shortest_code_path(index, a, b, *, theta, max_hops=6) -> (hops, directed)` (BFS over `code_out` skipping DEFINED_IN and ω < θ, neighbours in `(-ω, target)` order; if none, BFS over `code_out ∪ code_in` with `Hop.reverse=True`); `direct_edges(index, v, theta, limit=8)`; `code_paths_for(index, vertices, theta, max_hops=4)` (pairwise directed paths then direct edges, hops deduped); `render_triples(path)` → `billing.refund_service.apply_refund -[INVOKES 0.90]-> billing.ledger.post -[WRITES 0.85]-> table fin.ledger_entry` (reverse hop `a <-[K ω]- b`); `render_block(paths, max_chars)` (whole lines, `(… N more relations)` tail, `0` → `""`); `blast_radius(index, v, *, depth=2, theta, cap=200) -> BlastRadius(root, levels: [[Affected(node_id, name, kind, via, omega, through_id, community)]], total, truncated, tests: [node ids reachable by TESTED_BY])`: BFS over in-edges of INVOKES/OVERRIDES/IMPORTS/INHERITS, plus data objects the node WRITES and everyone who READS those, grouped by community in the rendering. Two more fixed tools from the code-only design: `exception_path(index, v, exception_name, *, theta, depth=4)` = symbols reachable from `v` over INVOKES (depth ≤ 4) whose `raises[]` or RAISES edge names the exception, intersected with callers of `v` that CATCH it → `{raisers: [hops...], catchers: [...]}`; `history(index, v, limit=3)` = the last `limit` commits with a MODIFIES edge to `v`, in PRECEDES order, each with sha, date, first message line and the hunk. `render_triples` prints `in_branch` and `arg_binding` from `extra` on INVOKES hops: `apply_refund -[INVOKES 0.90 in_branch args:{amount: -refund_amount}]-> ledger.post`. Simulation edge edits change the igraph PPR runs on, not these tools (docstring says so).

### 3.4 Retriever (`src/hippo/hipporag/retriever.py`)
- `SeedSymbol(symbol_id, name, qualname, kind, vertex, weight, anchor, how, specificity_count, boost, kept)`; `Trace` gains `seed_symbols`, `paths: list[list[dict]]`, `used_code_seeds`, `select: dict` (raw reply, decisions, error), `expansions`, `tests`, `history` (all defaulted; `trace_from_dict` tolerates old JSON). `retrieve()` reads the seven code settings; after the fact filter and **before the fallback decision**: anchors → weight `code_seed_weight × boost`, divided by `specificity` only when the `node_specificity` setting is on (same rule as entity seeds; `node_boosts` on symbol ids work; the boosts array is computed once for both seed families); dense seeds = the top `code_dense_seeds` code passages (those with `symbols_defined_in`) **by rank of the existing min-max `dpr_scores`** (skip zero scores; no cosine floor, which would be fragile under the fake's feature-hashed vectors) → their symbols with weight = `dpr_score × boost`, `how="dense"`; keep the top `MAX_CODE_SEEDS = 20` by weight (`kept`), zero the rest; `used_code_seeds = any kept > 0`. `linking_top_k` does **not** cut symbol seeds (it caps entities distilled from fuzzy fact matches; a stack-trace anchor is exact and must survive). Fallback becomes `if not kept_fact_indices and not trace.used_code_seeds`. `reset = phrase_weights + code_weights + passage_weights`. `seed_vertices` includes kept symbols; `TopNode.kind` may be `symbol`/`data`/`commit`. **Community prior**: after PPR, a passage whose defining symbol shares a community with any kept seed symbol gets `score × (1 + code_community_boost)` before ranking (recorded as `RankedPassage.community_boosted: bool = False`, defaulted so `RankedPassage(**p)` still loads stored traces). **Select pass** (`code_select` on and `used_code_seeds`): one `chat_json` call with `prompts.code_select_messages(question, [(title, preview 400 chars)] for the top 15)` and schema `{"decisions": [{"title", "action": keep|drop|expand}]}` (hippo's own prompt, DyRetriever style, one-shot example); dropped passages move below all kept ones (never removed: the trace shows them with `reason="dropped by select"`), "expand" fetches up to `code_expand_max` one-hop INVOKES/OVERRIDES/RAISES neighbours (ω ≥ 0.75) of the passage's symbols and records `trace.expansions: [{from, to, kind, omega, summary}]` where `summary` = the neighbour's signature + first doc line (never bodies); an `OllamaError` keeps the PPR order and notes it in `trace.select`. FakeOllama (`tests/fakes/fake_ollama.py`, a new dispatch rule keyed on the select system prompt; check `test_fakes.py` for an exhaustive dispatch assertion) answers the select prompt by keeping every passage that shares a content word with the question, and expanding the first one when the question contains "callees". `simulate()` replays `baseline.select` (like `baseline.filter`) unless `rerun_filter`, so Analyze-page slider tweaks cost no LLM call. After that: `trace.paths = code_paths_for(index, kept seeds + top code nodes (≤ 8), theta=code_theta)` rendered to dicts, timed as `timing["paths"]`; `trace.tests` = TESTED_BY targets of the kept symbols; `trace.history` = `history()` of the top 3 kept symbols. `code_seed_weight = 0` and `code_dense_seeds = 0` reproduce today's behaviour exactly (no select pass, no block).

### 3.5 Answer serialization (`prompts.py`, `hipporag/answerer.py`, `ask.py`)
Pseudo-passage, not a new prompt builder: `rag_qa` stays byte-identical (fidelity contract), the model already treats `Title:` blocks as evidence, and `FakeOllama.answer()` skips `Title:` lines. `prompts.CODE_GRAPH_TITLE = "Code graph"`, `CODE_GRAPH_HEADER` = one sentence explaining the notation (INVOKES = calls, READS/WRITES = uses/changes a table or collection, IMPORTS, INHERITS, CONTAINS; confidence 0–1 in brackets), marked "hippo's own"; `code_graph_passage(block) -> (title, text)`. `Answer` gains `context_block: str = ""`; `answer_question(ollama, question, passages, context_block="")` prepends the pseudo-passage (first, so it is never what a long passage list overflows). `ask.answer_from_trace`: `include = trace.used_code_seeds or any read passage defines a symbol`; `block = render_block(trace, settings["code_triples_chars"])` in the code-only design's order: `[PATH]` lines (with `in_branch`/`args`), `[COMMUNITY] <subsystem name> (N files)`, `[EXPANDED]` one-line summaries, `[TESTS] path::test_name (TESTED_BY ω)`, `[COMMIT sha10 "subject"]` for `trace.history`; passages follow as today with their titles (`path :: qualname (lines a-b)`), which already carry the file path. Simulations re-answer from the trace's own fields (no recomputation).

## Known limitations to state in the docs
- Cypher extraction reads literal labels and rel types only. hippo's own LadybugDB schema is Python dicts interpolated into `CREATE NODE TABLE {name}(...)`, so indexing hippo yields DataObjects for `Settings`, `Passage`, `Source`, … from the literal `MATCH`/`MERGE` strings, not from the table declarations. "Our own databases" means Cypher literals, not schema introspection.
- Import direction is clean: `codegraph` → `hipporag.text` only (`hipporag/__init__.py` has no imports); `ingest.chunker` → `codegraph.model`; `hipporag.indexer` imports `CodeGraph` under `TYPE_CHECKING`.
